# v8.4 Implementation Plan — Connected Data

> **Status:** Phase 0 — Design Only  
> **Do not begin implementation until Phase 0 is approved and committed.**

---

## Mission

**"One piece of information entered once, reused everywhere."**

Connect existing engines so that photos, OCR results, grading assessments, collection intelligence, market awareness, and session context automatically flow to every tool where they are relevant — without manual re-entry.

---

## Phase 1 — Connected Data Core Engine

### Scope
Design and implement `ConnectedContext` and `ConnectedDataEngine` — the thin cross-referencing facade.

### Files
- `connected_data.py` (new)
- `test_connected_data.py` (new)

### Tasks
1. [ ] Design `ConnectedContext` dataclass with all optional reference fields
2. [ ] Implement `ConnectedDataEngine` with `link_*()` methods:
   - `link_photos_to_grading()`
   - `link_ocr_to_grading()`
   - `link_intelligence_to_shopping()`
   - `link_market_to_acquisition()`
   - `link_watchlist_to_deals()`
   - `link_batch_to_grading()`
3. [ ] Implement `generate_cross_reference_report()`
4. [ ] Unit tests for all link methods (mock engine outputs)
5. [ ] Unit tests for `ConnectedContext` dataclass

### Acceptance Criteria
- `ConnectedDataEngine` can cross-reference mock engine outputs deterministically
- All link methods return structured dicts with `source`, `target`, `match_type`, `confidence` fields
- `generate_cross_reference_report()` returns a summary with counts per link type
- No new data models, no new persistence, no new business logic

- `test_ai_grading_assistant.py` (regression tests for new params)
- `test_smart_shopping_assistant.py` (regression tests for new params)
- `test_acquisition_workflow.py` (regression tests for new params)
- `test_deal_hunter.py` (regression tests for new params)
- `test_batch_processing.py` (regression tests for new params)
- `test_collection_assistant.py` (regression tests for new params)

### Tasks
1. [ ] Add keyword-only `ocr_report` param to `AIGradingAssistant.assess_candidate()`
   - If provided, auto-populate missing candidate fields from OCR
   - If photo_records provided, auto-link certification numbers
2. [ ] Add keyword-only params to `SmartShoppingAssistant.rank_candidates()`
   - Auto-boost WANT_LIST and gap-fill candidates
3. [ ] Add keyword-only `market_history` param to `AcquisitionWorkflow.evaluate()`
   - Include historical observed price context in reasoning
4. [ ] Add keyword-only `watchlist_matches` param to `DealHunter.analyze_listing()`
   - Flag watchlist matches automatically
5. [ ] Add keyword-only `grading_queue` param to `BatchProcessingEngine.process()`

6. [ ] Add keyword-only params to `CollectionAssistant.review_candidate()`

7. [ ] Regression tests for each engine: existing tests must pass unchanged
8. [ ] New tests: verify auto-population works with context, works without context

### Acceptance Criteria
- All existing tests pass without modification (keyword-only params with None defaults)
- New tests verify auto-population logic works correctly
- New tests verify graceful degradation when context is missing

## Risk Register

| Risk | Phase | Mitigation |
|------|-------|------------|
| Circular engine dependencies | Phase 2 | Keyword-only params; no engine imports another engine |
| Performance degradation | Phase 3 | Lazy cross-referencing; workspace cache |
| Breaking existing behavior | Phase 2 | None-default keyword-only params; regression tests |
| Scope creep | All | Architecture review at end of each phase |
| GUI complexity | Phase 5 | New tabs are optional; preserve existing patterns |
