# v8.8 Phase 3 Design: Image Assessment GUI Integration

Status: Design only  
Implementation: Not started  
Baseline: `b993066` with 1,430 tests passing

## Mission

Make deterministic Image Assessment visible and understandable in the GUI without adding new image-analysis behavior.

The GUI should help the collector answer:

> Are this collectible's photos good enough for the next task?

The GUI consumes `CollectorWorkspace.get_image_assessment(...)` only. It does not score images, identify coins, grade coins, or recommend submission.

## Current State

The application already has:

- `ImageAssessmentEngine` for deterministic Level A image readiness.
- `CollectorWorkspace.get_image_assessment(...)` for item, candidate, and explicit photo-set assessment.
- `ImageAssessmentReport` with serialization and markdown export.
- Reports Panel descriptor: `image_assessment`.
- Existing `Collector Workspace` GUI with notebook tabs and text-format panels.
- Existing `Photo Vault` tab focused on coverage and audit counts.

No dedicated Image Assessment GUI exists yet.

## 1. Recommended GUI Placement

Recommended placement: add a new `Image Readiness` tab inside the existing `Collector Workspace`.

Rationale:

- It reuses the existing read-only workspace pattern.
- It avoids changing item-entry, OCR, grading, or Photo Vault ownership.
- It keeps Image Assessment near Photo Vault without making Photo Vault responsible for quality scoring.
- It can be refreshed through the existing workspace refresh flow.
- It gives future GUI work a stable, visible entry point.

Do not replace the existing `Photo Vault` tab. Photo Vault should continue to answer:

> Which items have photos, and are photo references intact?

Image Readiness should answer:

> Are the selected item's photos suitable for downstream analysis?

## 2. Layout

Use the existing `Collector Workspace` visual pattern:

- notebook tab
- top controls row
- read-only text output
- small button row

Proposed tab title:

```text
Image Readiness
```

Top controls:

- item selector combobox or compact searchable selector
- optional `Certified item` checkbox if no reliable item metadata already exposes that state
- `Assess` button
- `Refresh` button
- `Export Markdown` button if tied to the current assessment report

Read-only output sections:

Use text formatting first. Do not introduce thumbnail rendering in Phase 3.

## 3. Selection Model

Primary Phase 3 selection:

- assess one existing collection item at a time
- call `workspace.get_image_assessment(item_id=item.id)`

Selector population:

- include collection items that have `photos` or legacy `image_path`
- show compact collector-facing labels:
  - year
  - country
  - denomination
  - grade where available
  - id as a fallback

Default selection:

- if the main collection table has a selected item and the GUI can safely read it, preselect that item
- otherwise show the first item with photos
- if no items have photos, show an empty state

Future-supported but not required in Phase 3:

- explicit photo-set assessment from Photo Inbox
- candidate assessment
- item-detail embedded assessment

Do not mutate collection items or photo records while building selections.

## 4. Empty, Error, and Degraded States

Empty collection:

```text
No collection items are available for image assessment.
```

No items with photos:

```text
No items with attached photos are available.
Attach front and back photos before running image readiness.
```

No selected item:

```text
Select an item to assess its photos.
```

Missing or unreadable image:

- show the valid report returned by `CollectorWorkspace.get_image_assessment(...)`
- include blocking issues and recommended actions
- do not prevent the tab from opening

Workspace/engine failure:

- show `engine_errors` using the existing warning formatting pattern
- keep the tab usable
- do not show modal errors unless the report cannot be displayed at all

The collector should always get a readable explanation instead of a crash or silent failure.

## 5. Per-Photo vs Photo-Set Presentation

Photo-set summary should appear first:

- score
- decision
- confidence
- downstream readiness
- missing roles
- blocking issues
- recommended actions

Per-photo details should be secondary:

- path basename, not full path by default
- role
- decision
- score
- strengths
- issues
- blocking issues
- recommended actions

Do not overemphasize raw numeric metrics such as brightness, contrast, or sharpness. These can remain hidden unless a future diagnostic view is approved.

## 6. Navigation Behavior

Recommended Phase 3 navigation:

- Add `Image Readiness` as a tab in `open_collector_workspace()`.
- Keep the Reports Panel `Image Assessment Readiness` descriptor unchanged.
- In the new tab, let the collector choose an item and assess it.
- `Export Markdown` exports the currently displayed assessment if feasible.

Optional but safe if implementation is simple:

- Add a button from `Photo Vault` tab:
  - `Open Image Readiness`
  - selecting that button switches to the Image Readiness tab

Do not add a new top-level window unless the existing workspace tab pattern proves too constrained.

Do not alter item details in Phase 3. Item-detail integration can be a later refinement once the workspace tab is stable.

## 7. Refresh Behavior

Workspace-level `Refresh Workspace`:

- calls `workspace.refresh()`
- clears cached Image Assessment reports
- preserves the lazy engine instance, matching Phase 2 behavior
- refreshes the Image Readiness tab for the currently selected item if one exists

Tab-level `Refresh`:

- re-runs `workspace.get_image_assessment(item_id=..., refresh=True)`
- keeps the same selected item
- updates the read-only output

Changing the selected item:

- should run assessment when the collector clicks `Assess`
- may optionally auto-run after selection changes only if it remains responsive

Avoid background scanning, watchers, or automatic imports.

## 10. Regression Risks

Primary risks:

- accidentally adding image scoring logic to the GUI
- turning photo readiness into grading or submission advice
- making the workspace dialog too slow by assessing every item automatically
- breaking the existing workspace refresh path
- exposing raw metrics in a way that looks more authoritative than Level A supports
- mutating item photo metadata while preparing display labels
- staging unrelated deleted debug/test image artifacts

Mitigations:

- assess only the selected item
- call only `CollectorWorkspace.get_image_assessment(...)`
- keep display formatting separate from analysis
- keep thumbnail rendering out of Phase 3
- test existing Photo Vault and Reports Panel behavior
- review `git status --short` before staging

## 11. Explicit Out of Scope

Phase 3 must not include:

- new image-analysis logic
- Level B computer vision
- OCR changes
- coin identification
- variety attribution implementation
- grade prediction
- grading-readiness recommendation
- Canadian Reference provider work
- catalogue/provider implementation
- external APIs
- web scraping
- networking
- file copy, move, rename, correction, replacement, or deletion
- collection mutation
- photo-record mutation
- persistence redesign
- Photo Vault ownership changes
- Photo Inbox workflow changes
- thumbnail gallery redesign
- unrelated GUI redesign

## Recommended Implementation Sequence

1. Add formatter helper for `ImageAssessmentReport`.
2. Add helper to build collector-facing item selector labels.
3. Add `_create_image_readiness_tab(...)` to the existing workspace dialog.
4. Insert the tab near `Photo Vault`.
5. Add tab refresh behavior to `_refresh_workspace_tabs(...)`.
6. Add optional markdown export for the currently displayed assessment only if it stays simple.
7. Add focused GUI/workspace tests.
8. Run `python -m unittest test_collector_workspace.py`.
9. Run `python -m unittest discover`.

Stop after GUI visibility. Do not begin Canadian Reference Intelligence, OCR, identification, grading, or grading-readiness work.
