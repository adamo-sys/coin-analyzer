# v8.8 Phase 5 Design: Canadian Reference Workspace Integration

Status: Design only
Implementation: Not started
Baseline: Phase 4C complete at `320a1fa` with 1,488 tests passing

## Mission

Expose configured Canadian reference-provider data through `CollectorWorkspace` as a deterministic, read-only report API.

Phase 5 connects the completed provider core to the workspace's existing lifecycle, cache, report registry, and Markdown export patterns. It does not identify a coin, rank candidates, infer a match from a collection item, or load any catalogue data.

```text
ReferenceProviderAggregator
-> CollectorWorkspace.get_canadian_references(...)
-> workspace report / Markdown export
-> future GUI
```

## Current State

Phase 4 provides:

- `ReferenceProvider` contracts and neutral DTOs
- local JSON and manual providers
- deterministic `ReferenceProviderAggregator`
- exact normalized-`issue_id` grouping only
- claim-level provenance and conflict DTOs
- provider-failure isolation and aggregate validation

`CollectorWorkspace` already provides:

- lazy `_get_engine(...)` / `_create_engine(...)` lifecycle
- session-only `_cache`
- `refresh()` that clears reports but preserves engine instances
- `WorkspaceReport` wrappers and deterministic `to_dict()` use
- `ReportDescriptor`, `get_reports()`, `generate_report(...)`, and `export_report(...)`
- report-object Markdown export fallback

No workspace constructor input, report DTO, cache key, descriptor, or public method currently exposes Canadian reference data.

## 1. Public API

Add one read-only workspace entry point:

```python
def get_canadian_references(
    self,
    *,
    issue_id: str = "",
    query: Optional[ReferenceQuery] = None,
    filters: Optional[ReferenceFilters] = None,
    refresh: bool = False,
) -> CanadianReferenceReport:
    ...
```

Valid request modes are mutually exclusive:

| Mode | Accepted input | Aggregator call |
| --- | --- | --- |
| Exact issue | non-empty `issue_id` only | `aggregator.get_issue(issue_id)` |
| Search | `ReferenceQuery` only | `aggregator.search(query)` |
| Filtered list | `ReferenceFilters` only | `aggregator.list_issues(filters)` |
| No selection | no input | no provider call; degraded report |

If more than one selection input is supplied, return a degraded `CanadianReferenceReport` with a clear request error. Do not silently give one mode precedence over another.

`issue_id` means exact normalized issue-ID lookup only. It must not fall back to country/year/denomination matching. `query` and `filters` are passed unchanged to the aggregator; `CollectorWorkspace` must not add matching, ranking, or normalization rules.

## 2. Input And Query Model

The workspace constructor gains optional injection points:

```python
def __init__(
    self,
    collection_items: List[Any],
    *,
    ...,
    reference_providers: Optional[List[Any]] = None,
    reference_provider_aggregator: Optional[Any] = None,
):
    ...
```

Rules:

- `reference_provider_aggregator` is for callers that already own a configured `ReferenceProviderAggregator`.
- `reference_providers` is for callers that want the workspace to lazily create an aggregator around an explicit provider list.
- Passing both is invalid constructor configuration; raise `ValueError` immediately rather than guessing ownership.
- Passing neither remains valid and preserves current workspace behavior.
- The workspace must not read a local reference path, create a default provider, discover providers, import data, or persist provider configuration in this phase.

No collection item input is accepted. A collection item's country, year, denomination, text, photos, OCR data, or notes must never be converted into a reference query in Phase 5. That would be matching/inference work.

## 3. DTO Ownership

Add a workspace wrapper only:

```python
@dataclass
class CanadianReferenceReport(WorkspaceReport):
    selection_type: str = ""
    issue_id: str = ""
    query: Dict[str, str] = field(default_factory=dict)
    filters: Dict[str, str] = field(default_factory=dict)
    provider_ids: List[str] = field(default_factory=list)
    group_count: int = 0
    record_count: int = 0
    claim_count: int = 0
    conflict_count: int = 0
    provider_error_count: int = 0
    validation_error_count: int = 0
    aggregate_result: Any = None
    validation_report: Any = None
    summary: Dict[str, Any] = field(default_factory=dict)
```

Ownership rules:

- `canadian_reference_provider.py` remains the owner of providers, aggregation, issue groups, source claims, conflict detection, and validation.
- `collector_workspace.py` owns only request metadata, report counts, cache/lifecycle integration, degraded-state messages, and presentation serialization.
- `CanadianReferenceReport` carries Phase 4 DTOs unchanged. It does not create a merged canonical issue, selected value, conflict winner, candidate, confidence, or recommendation.
- `to_dict()` delegates nested serialization through existing `to_dict()` methods.

## 4. Provider Lifecycle

Add a lazy workspace engine branch:

```python
elif name == "canadian_references":
    from canadian_reference_provider import ReferenceProviderAggregator

    if self._reference_provider_aggregator is not None:
        return self._reference_provider_aggregator
    return ReferenceProviderAggregator(self._reference_providers or ())
```

Lifecycle rules:

- Do not create an aggregator during `CollectorWorkspace.__init__`.
- Do not instantiate or mutate providers from the GUI.
- Reuse one configured aggregator for the workspace lifetime.
- `refresh()` clears cached reference reports but preserves the aggregator and provider instances.
- A no-selection request returns a degraded report before creating the engine.
- A valid request with no configured providers returns a degraded report after lazy creation, with `No Canadian reference providers configured.` in `engine_errors`.

The workspace does not inspect provider internals, paths, JSON schema, manual records, licences, or source priority. It calls only the Phase 4 aggregate public API.

## 5. Cache Strategy

Use the existing session-only workspace cache.

Recommended key payload:

```python
{
    "namespace": "canadian_references",
    "selection_type": "issue_id|query|filters|none",
    "issue_id": normalize_text(issue_id),
    "query": query.to_dict() if query else {},
    "filters": filters.to_dict() if filters else {},
    "provider_ids": list(aggregator.provider_ids()),
}
```

Hash the canonical JSON payload as existing workspace cache helpers do:

```text
canadian_references:<sha256-prefix>
```

Rules:

- Do not mutate input DTOs when building the key.
- The provider-ID list distinguishes separately configured provider sets.
- `refresh=True` bypasses only the matching report key.
- `workspace.refresh()` clears all reference-report cache entries and retains the aggregator instance.
- Do not cache inside providers or persist workspace results to disk.
- Provider data changed outside the workspace becomes visible after explicit `refresh=True` or `workspace.refresh()`.

No filesystem timestamps, provider polling, watchers, cloud checks, or background refresh are allowed.

## 6. Error And Degraded-State Handling

Ordinary problems return a valid `CanadianReferenceReport`; they must not raise into a future GUI.

| Case | Report behavior |
| --- | --- |
| No selection | `selection_type="none"`, no engine creation, clear workspace error. |
| Conflicting request modes | `selection_type="invalid"`, no aggregate call, clear workspace error. |
| Invalid query/filter DTO type | degraded report, no aggregate call. |
| No providers configured | valid report with no groups and a configuration error. |
| Provider returns a structured error | preserve it in `aggregate_result.provider_errors`. |
| One provider throws | preserve aggregate structured error; healthy provider groups remain visible. |
| Aggregator raises unexpectedly | degraded report with a concise workspace error, no stack trace. |
| Aggregate validation has findings/errors | preserve the complete validation DTO and expose summary counts. |

`engine_errors` belongs only to workspace request/configuration/invocation failures. Provider-specific errors and validation findings remain in their Phase 4 DTOs with provider identity intact.

## 7. Conflict And Provenance Presentation

The workspace report must make Phase 4 information visible without interpreting it:

- `aggregate_result.groups` exposes each exact-ID group.
- each group retains every `ReferenceRecord` and every `ReferenceClaim`.
- each conflict retains its field name, conflict type, and all disagreeing claims.
- each claim retains provider ID, `ReferenceSource`, source-record ID, raw value, normalized value, and optional `SourceRef`.

Summary counts are factual only:

- provider count
- group count
- record count
- claim count
- conflict count
- aggregate provider-error count
- aggregate validation error/warning count

Forbidden workspace presentation concepts:

- correct value
- preferred source
- winning claim
- manual override
- likely issue
- match score
- candidate confidence
- recommendation

Manual records continue to appear as ordinary attributed claims. Their presence must not change ordering, reporting, or conflict behavior beyond the Phase 4 aggregator's deterministic registration order.

## 8. Reports Panel Behavior

Add a descriptor only when reference providers or an injected aggregator were supplied:

```python
ReportDescriptor(
    name="canadian_references",
    title="Canadian Reference Claims",
    category="Reference",
    description="Configured Canadian reference claims, provenance, and conflicts",
    engine_name="canadian_references",
    method_name="get_canadian_references",
    has_markdown_export=True,
    has_csv_export=False,
    available=bool(self._reference_providers) or self._reference_provider_aggregator is not None,
)
```

The descriptor is metadata only; it must not instantiate the aggregator or query providers.

`generate_report("canadian_references")` calls `get_canadian_references()` with no selection. When providers are configured, this returns the deliberate no-selection/degraded report. It must not list every record, scan a provider, or infer a query from the collection simply to populate a generic report menu.

Future GUI integration may call `get_canadian_references(issue_id=...)`, `query=...`, or `filters=...` explicitly.

## 9. Markdown And Export Decision

Markdown export is approved because the report is provenance and explanation focused. CSV is deferred: flattening groups, repeated source claims, and conflicts would obscure their relationships.

`CanadianReferenceReport.to_markdown()` should render:

1. request mode and supplied exact issue ID/query/filter values
2. configured provider IDs
3. summary counts
4. issue groups, retaining every source record
5. source claims with source name, source-record ID, raw value, and normalized value
6. conflict sections showing all competing claims without a selected value
7. provider errors
8. validation findings
9. workspace errors

The export must use the existing `export_report(...)` fallback to the report object's `export_markdown(path)` method. Do not create a second export API or attach source files, photos, catalogue extracts, or other data.

## 12. Regression Risks

| Risk | Mitigation |
| --- | --- |
| Workspace duplicates provider conflict logic | Carry Phase 4 aggregate DTOs through unchanged. |
| A collection item becomes an implicit search query | Accept only explicit issue ID, query, or filters. |
| Report menu triggers a broad provider scan | No-selection descriptor invocation returns a degraded report. |
| Manual records become implicit winners | Preserve aggregator output; add no source-priority behavior. |
| Provider state changes are hidden indefinitely | Reuse existing `refresh=True` and `workspace.refresh()` semantics. |
| Provider errors are converted into vague UI strings | Retain structured provider errors in nested result DTOs. |
| Workspace creates providers or reads catalogue data | Require injected providers/aggregator and add no source configuration. |
| Future GUI consumes a premature matching API | Keep exact/query/filter request modes explicit and read-only. |

## 13. Explicit Out Of Scope

Phase 5 must not include:

- fuzzy matching, candidate identification, or ranking
- collection-item-to-reference matching
- OCR, photo, image-assessment, or variety-attribution changes
- grading, grading readiness, pricing, or market analysis
- GUI or CollectorWorkspace view changes
- provider mutation, manual-record editing, or provider configuration persistence
- local path discovery, catalogue import, scraping, website automation, APIs, networking, cloud sync, polling, or watchers
- Charlton, Coins and Canada, Numista, commercial, licensed, or proprietary catalogue ingestion/content
- conflict resolution, source priority, manual override precedence, or winner selection
- collection mutation, collection persistence, file movement, or schema migration

## Recommended Implementation Sequence

1. Add optional provider/aggregator constructor inputs with mutually exclusive validation.
2. Add `CanadianReferenceReport` with nested Phase 4 DTO serialization and Markdown export.
3. Add lazy `canadian_references` engine creation using explicit injected configuration only.
4. Add request validation and `get_canadian_references(...)` delegation.
5. Add deterministic cache-key and degraded-report helpers.
6. Add report descriptor and `_invoke_report_method(...)` branch.
7. Extend the existing workspace tests with synthetic providers and aggregate DTO assertions.
8. Run focused workspace tests.
9. Run full unittest discovery.

Stop after Phase 5 workspace integration. GUI, matching, identification, catalogue ingestion, OCR, grading, pricing, and override persistence require separate design approval.
