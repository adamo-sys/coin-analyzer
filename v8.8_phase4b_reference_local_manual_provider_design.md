# v8.8 Phase 4B Design: Local And Manual Reference Providers

Status: Design only
Implementation: Not started
Baseline: Phase 4A complete at `a3ef9a9` with 1,456 tests passing

## Mission

Implement concrete local/manual reference providers using only user-owned, synthetic, or openly licensed data.

Phase 4B proves that the Phase 4A provider contracts work with safe local data before any aggregation, identification, GUI, OCR, grading, pricing, or catalogue-ingestion work begins.

## 1. Exact Provider Public APIs

Both concrete providers should implement the existing `ReferenceProvider` protocol exactly:

```python
def provider_id(self) -> str: ...
def capabilities(self) -> ReferenceProviderCapabilities: ...
def get_source_metadata(self) -> ReferenceSource: ...
def validate(self) -> ReferenceValidationReport: ...
def get_issue(self, issue_id: str) -> Optional[ReferenceRecord]: ...
def search(self, query: ReferenceQuery) -> ReferenceSearchResult: ...
def list_issues(self, filters: Optional[ReferenceFilters] = None) -> ReferenceSearchResult: ...
```

### LocalJsonReferenceProvider

Recommended constructor:

```python
class LocalJsonReferenceProvider:
    def __init__(self, path: str, provider_id: str = ""):
        ...
```

Recommended additional methods:

```python
def load(self) -> ReferenceValidationReport: ...
def loaded(self) -> bool: ...
```

Rules:

- `load()` reads the local JSON file and builds immutable `ReferenceRecord` objects.
- `load()` may be called explicitly, but query methods may lazily call it once.
- no writes in Phase 4B
- no network
- no scraping
- no schema migration writer

### ManualReferenceProvider

Recommended constructor:

```python
class ManualReferenceProvider:
    def __init__(
        self,
        records: Optional[Iterable[ReferenceRecord]] = None,
        source: Optional[ReferenceSource] = None,
        provider_id: str = "manual-reference",
    ):
        ...
```

Recommended mutation methods:

```python
def add_record(self, record: ReferenceRecord) -> ReferenceValidationReport: ...
def replace_records(self, records: Iterable[ReferenceRecord]) -> ReferenceValidationReport: ...
def export_json(self, path: str) -> bool: ...
```

Rules:

- mutations affect only the provider's in-memory record list
- no collection mutation
- no file writes except explicit `export_json(...)`
- manual data is assumed user-owned
- source type defaults to `MANUAL`

## 2. Local JSON Schema

Schema version: `1`

Recommended shape:

```json
{
  "schema_version": 1,
  "provider_id": "synthetic-canadian-reference",
  "source": {
    "source_id": "synthetic-canadian-reference",
    "source_name": "Synthetic Canadian Reference",
    "source_type": "SYNTHETIC_TEST",
    "edition": "2026 test",
    "url": "",
    "licence": "Synthetic test data",
    "attribution": "Synthetic fixture only",
    "retrieved_at": "",
    "notes": ""
  },
  "issues": [
    {
      "issue_id": "ca-1920-cent-synthetic",
      "country": "Canada",
      "authority": "Dominion of Canada",
      "denomination": "1 Cent",
      "year": "1920",
      "date_text": "1920",
      "monarch": "George V",
      "series": "Synthetic Small Cent",
      "mint": "",
      "mintmark": "",
      "variety": "",
      "composition": "Bronze",
      "weight": "3.24 g",
      "diameter": "19.05 mm",
      "shape": "Round",
      "orientation": "Medal",
      "mintage": "synthetic test value",
      "catalogue_numbers": {
        "synthetic": "TEST-1920-CENT"
      },
      "design_markers": [
        "synthetic obverse marker",
        "synthetic reverse marker"
      ],
      "notes": "Synthetic fixture only. Not copied from a proprietary catalogue.",
      "source_record_id": "row-1",
      "source_refs": [
        {
          "source_id": "synthetic-canadian-reference",
          "source_record_id": "row-1",
          "field_name": "denomination",
          "raw_value": "1 Cent",
          "normalized_value": "1 cent",
          "confidence": 1.0,
          "notes": ""
        }
      ]
    }
  ]
}
```

Schema rules:

- `schema_version` is required.
- `source` is required.
- `issues` is required and defaults to empty only when present as `[]`.
- each issue maps to one `ReferenceRecord`.
- each issue's `source_record_id` becomes the record's `source_record_id`.
- if an issue has no `source_refs`, provider validation should warn but still load the record.
- no proprietary copied content in fixtures.

## 3. Manual Provider Ownership And Mutation Rules

Manual provider owns only its in-memory record collection.

Allowed:

- add user-owned `ReferenceRecord`
- replace in-memory records explicitly
- export current records to JSON when requested
- validate after changes

Forbidden:

- mutating collection items
- mutating `ReferenceRecord` / `CanadianIssue` DTOs in place
- silently merging records from other providers
- writing files except through explicit `export_json(path)`
- treating manual records as higher priority than other providers in Phase 4B

Manual records are source claims, not conflict resolutions. Any future "user override wins" behavior belongs to Phase 4C or later.

## 4. Search And Filter Semantics

Search is deterministic, local, and simple.

`search(query)`:

- normalizes query text
- searches across:
  - issue id
  - country
  - authority
  - denomination
  - year
  - date text
  - monarch
  - series
  - mintmark
  - variety
  - composition
  - catalogue numbers
  - design markers
- returns records whose normalized searchable text contains all non-empty query tokens
- applies structured fields in `ReferenceQuery` as filters when present

`list_issues(filters)`:

- returns all records if filters are empty
- supports exact normalized matching for:
  - country
  - denomination
  - year
  - authority
  - monarch
  - series

No fuzzy ranking in Phase 4B. No scoring. No identification.

## 5. Deterministic Ordering

All provider outputs should use `sort_reference_records(...)`.

Ordering:

```text
normalized country
normalized denomination
normalized year/date
normalized variety
issue_id
```

JSON export ordering:

- source keys in stable order
- issue records sorted by `sort_reference_records(...)`
- catalogue number keys sorted
- source refs emitted in input order unless implementation chooses stable field/source order

## 6. Validation Flow

Local provider:

1. parse JSON
2. check schema version
3. build `ReferenceSource`
4. build issue DTOs
5. build `ReferenceRecord` list
6. run `validate_records(provider_id, records)`
7. append loader-level findings for parse/schema problems

Manual provider:

1. accept records
2. coerce iterable to tuple/list internally
3. run `validate_records(provider_id, records)`
4. return validation report

Provider query behavior:

- query methods should return structured provider errors if loading failed
- a malformed local file should not throw during search/list/get once provider catches it
- constructor should not throw for ordinary malformed file content; `load()` / query should report it

## 7. Error Handling

Expected error codes:

- `LOCAL_REFERENCE_FILE_MISSING`
- `LOCAL_REFERENCE_JSON_MALFORMED`
- `LOCAL_REFERENCE_SCHEMA_UNSUPPORTED`
- `LOCAL_REFERENCE_SCHEMA_MISSING`
- `LOCAL_REFERENCE_SOURCE_MISSING`
- `LOCAL_REFERENCE_ISSUES_MISSING`
- `LOCAL_REFERENCE_RECORD_INVALID`
- `LOCAL_REFERENCE_LOAD_FAILED`
- `REFERENCE_PROVIDER_NOT_LOADED`
- `REFERENCE_EXPORT_FAILED`

Rules:

- malformed JSON returns a validation report with `ERROR`
- missing file returns provider error, not stack trace
- unsupported schema version returns provider error and no loaded records
- one invalid record should not block other valid records unless the whole file cannot be parsed
- provider errors appear in `ReferenceSearchResult.provider_errors`
- warnings remain human-readable

## 8. Version Compatibility

Phase 4B supports schema version `1`.

Behavior:

- missing schema version: error
- version `1`: supported
- future version higher than supported: error
- lower unsupported versions: error unless explicit compatibility is added later

Do not add automatic migrations in Phase 4B.

## 9. Import And Export Behavior

LocalJsonReferenceProvider:

- imports from local JSON file only
- read-only in Phase 4B
- no export method required

ManualReferenceProvider:

- initializes from in-memory `ReferenceRecord` objects
- may export to schema version `1` JSON through `export_json(path)`
- export is explicit only
- export should be deterministic

No CSV import/export in Phase 4B.

No external API import/export.

## 12. Regression Risks

Risks:

- accidentally adding catalogue-specific assumptions to the JSON schema
- turning search into identification/ranking
- adding file writes to local provider
- treating manual data as an implicit winner over other sources
- losing raw values during normalization
- permitting malformed local files to throw stack traces into callers
- creating fixtures from proprietary reference data
- adding network behavior under an open-provider umbrella

Mitigations:

- synthetic fixtures only
- provider errors in DTOs
- local provider read-only
- manual export explicit only
- no ranking/scoring
- no aggregation/conflict resolution
- tests for raw-value preservation
- tests for no network behavior

## 14. Recommended Implementation Sequence

1. Add schema constants for local reference JSON version `1`.
2. Add small coercion helpers from dict to `ReferenceSource`, `CanadianIssue`, `SourceRef`, and `ReferenceRecord`.
3. Add `LocalJsonReferenceProvider` with lazy `load()`.
4. Add provider-level structured error handling.
5. Add deterministic search/filter helpers shared by local/manual providers.
6. Add `ManualReferenceProvider` with in-memory add/replace.
7. Add explicit deterministic `export_json(path)` for manual provider.
8. Add focused tests using synthetic records.
9. Run `python -m unittest test_reference_provider_core.py` or the new focused provider test file.
10. Run `python -m unittest discover`.

Stop after Phase 4B. Do not begin aggregation, conflict handling, identification, OCR, GUI, grading, pricing, or catalogue ingestion.
