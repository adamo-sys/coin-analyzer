# v8.3 Collector Workspace Implementation Plan

## Overview

Collector Workspace (v8.3) is the unified operating system layer that transforms the application from a collection of standalone tools into a cohesive collector experience. It aggregates existing engines into organized, actionable panels without adding new intelligence, new data models, or new collection storage.

## Design Principle

**Aggregator only. No data ownership. No intelligence duplication.**

The workspace queries existing engines and displays their outputs. Existing engines remain the source of truth.

## Permanent Architectural Rule

**Workspace = ViewModel, not Business Logic.**

CollectorWorkspace contains **zero business logic**. It only requests, caches, and presents results from existing engines. The workspace never computes duplicate detection, upgrade opportunities, grade analysis, want list logic, AI grading, batch processing, quality scoring, or integrity audit. Those computations belong to existing engines. The workspace aggregates their results.

## API-First Design

```python
class CollectorWorkspace:
    """Unified workspace — thin aggregation layer. No data ownership. No mutation."""

    def __init__(self, collection_items, ...):
        """Initialize with existing engines. No collection copy."""

    def refresh(self) -> None:
        """Refresh all panels by re-querying source engines."""

    def get_dashboard(self) -> DashboardReport:
        """Unified daily dashboard with health, priorities, actions."""

    def get_inbox(self) -> InboxReport:
        """Consolidated review queue across all subsystems."""

    def get_collection_overview(self) -> CollectionOverviewReport:
        """One-glance collection snapshot."""

    def get_want_list(self) -> WantListReport:
        """Upgrade candidates, gaps, and watchlist targets."""

    def get_opportunities(self) -> OpportunitiesReport:
        """Shopping opportunities and purchase pipeline."""

    def get_ai_queue(self) -> AIQueueReport:
        """Pending AI Grading assessments and batch results."""

    def get_batch_queue(self) -> BatchQueueReport:
        """Batch processing sessions and review status."""

    def get_photo_vault(self) -> PhotoVaultReport:
        """Photo coverage, integrity, and missing photo summary."""

    def get_workflow_status(self) -> WorkflowStatusReport:
        """Active workflows and today's tasks."""

    def get_data_safety(self) -> DataSafetyReport:
        """Backup readiness, integrity warnings, persistence status."""

    def get_reports(self) -> ReportsMenu:
        """Unified access to all existing report engines."""
```

## Phase Breakdown

### Phase 1 — Core Engine
- Design `CollectorWorkspace` with thin aggregation architecture
- Implement `WorkspacePanel`, `WorkspaceReport`, `DashboardReport` dataclasses
- Implement `refresh()` method that re-queries all source engines
- Implement lazy loading (panels only query when first accessed)
- Unit tests for public API structure

### Phase 2 — Panel Aggregation
- Implement `get_dashboard()` using `CollectorHomeDashboard` + `CollectorOperatingSystem`
- Implement `get_inbox()` using `CollectionAssistant` + `BatchProcessing` + `AIGradingAssistant`
- Implement `get_collection_overview()` using `CollectionIntelligence` + `CollectionDashboard` + `CollectionSnapshot`
- Implement `get_want_list()` using `CollectionIntelligence` + `WatchlistEngine` + `OpportunityEngine`
- Implement `get_opportunities()` using `SmartShoppingAssistant` + `OpportunityEngine` + `DealHunter`
- Implement `get_ai_queue()` using `AIGradingAssistant`
- Implement `get_batch_queue()` using `BatchProcessingEngine`
- Implement `get_photo_vault()` using `PhotoVault` + `PhotoVaultIntegrityAudit`
- Implement `get_workflow_status()` using `CollectorWorkflowEngine`
- Implement `get_data_safety()` using `PersistenceManager` + `CollectionIntegrityAudit`
- Unit tests for each panel (mock-based: verify correct engine methods are called)

### Phase 3 — Reports Panel
- Implement `get_reports()` as a menu/aggregator of existing report engines
- Wire each report to its existing engine without duplicating logic
- Export support: delegate to existing engine export methods
- Unit tests

### Phase 4 — Refresh & Lifecycle
- Implement `refresh()` that re-queries all engines on demand
- Implement lazy loading (panels only query when activated)
- Implement error handling: panel shows warning if engine fails, workspace does not crash
- Implement panel-level caching (optional, short-lived) with invalidation on refresh
- Unit tests for refresh, error handling, lazy loading

### Phase 5 — GUI Integration
- Add `Collector Home -> Collector Workspace` menu item (or elevate to default home view)
- Implement notebook/tabbed panel layout
- Implement each panel's read-only display using existing `ttk.Notebook` and `tk.Text` patterns
- Implement "Open in [Tool]..." buttons that launch existing dialogs for mutation
- Implement export buttons for each panel (delegate to existing engines)
- Unit tests for GUI wiring (import checks, smoke tests)

### Phase 6 — Release
- Final regression (1047+ baseline + new tests)
- Metadata updates
- Tag `v8.3`
- Commit and push
- Verify remote

## Guardrails

- No duplicated intelligence: every analysis comes from an existing engine
- No duplicated collection: workspace does not copy or cache collection data
- No ML: no new machine learning, neural networks, or AI models
- No CV: no computer vision, image recognition, or image analysis
- Read-only aggregation: workspace queries and displays; mutation flows through existing tools
- Thin orchestration: existing engines remain the source of truth
- Refresh on demand: panels re-query engines, never read stale cached data
- No new database: no new storage format, JSON file, or persistence layer
