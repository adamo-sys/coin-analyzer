# v8.8 Phase 2 Design: Image Assessment Workspace Integration

Status: Design only  
Implementation: Not started  
Baseline: v8.8 Phase 1 complete at `ba6a820` with 1,418 tests passing

## Mission

Expose the deterministic Level A Image Assessment Layer through `CollectorWorkspace` so the rest of the application can ask one read-only question:

> Are these photos suitable for downstream collector tasks?

This phase does not add new image analysis. It connects the existing `ImageAssessmentEngine` to the workspace aggregation, cache, lifecycle, and report patterns that already exist.

## Current State

`image_assessment.py` owns the Level A assessment logic and DTOs:

- `ImageAssessmentEngine`
- `PhotoQualityAssessment`
- `PhotoSetReadinessReport`
- `DownstreamUse`
- `DownstreamPermission`
- `ImageReadinessDecision`
- `ImageAssessmentConfidence`
- `ImageIssueSeverity`

`CollectorWorkspace` already provides:

- report DTOs derived from `WorkspaceReport`
- lazy engine creation through `_get_engine()` and `_create_engine()`
- report caching through `_cache`
- `refresh()` cache invalidation
- `get_reports()` and `_report_registry()`
- `generate_report(...)`
- `export_report(...)`

There is no current `CollectorWorkspace` entry point for Image Assessment.

## 1. Public API

Add one main workspace entry point:

```python
def get_image_assessment(
    self,
    *,
    item_id: str = "",
    candidate_id: str = "",
    photos: Optional[List[Any]] = None,
    certified_expected: bool = False,
    refresh: bool = False,
) -> ImageAssessmentReport:
    ...
```

Recommended behavior:

- `photos` is the highest-priority input when provided.
- `item_id` selects an existing collection item from `self._collection_items`.
- `candidate_id` selects a photo candidate from `self._photo_candidates` only if existing candidate objects expose usable photo references.
- no selection returns a degraded report instead of raising.
- `refresh=True` bypasses the cached assessment for the selected input.

Do not add multiple public methods unless implementation proves this single method is awkward. A single entry point keeps the workspace surface small and matches the existing report-oriented style.

## 2. Input and Selection Model

Input precedence:

1. Explicit `photos`
2. `item_id`
3. `candidate_id`
4. no selection

Explicit photos:

- Accept existing `ItemPhoto` objects and any photo-like objects already accepted by `ImageAssessmentEngine.assess_photos(...)`.
- Do not normalize, rewrite, or mutate the supplied objects.

Item selection:

- Find the first collection item whose `id` matches `item_id`.
- Assess the item through `ImageAssessmentEngine.assess_item(...)`.
- Use the item's normalized photo model as implemented by Phase 1B and Phase 1C.

Candidate selection:

- Support only current candidate/photo-reference structures that already exist in the repository.
- If a candidate has no reliable photo list, return a degraded report explaining that no assessable photos were found.
- Do not invent a new candidate schema in this phase.

No selection:

- Return an `ImageAssessmentReport` with `selection_type="none"`, no assessed photos, and a clear engine error or warning reason.
- Do not raise for ordinary no-selection use.

## 3. DTO Ownership

Add a workspace wrapper DTO only if needed:

```python
@dataclass
class ImageAssessmentReport(WorkspaceReport):
    selection_type: str = ""
    selection_id: str = ""
    item_id: str = ""
    candidate_id: str = ""
    photo_count: int = 0
    blocking_issue_count: int = 0
    warning_count: int = 0
    readiness_report: Optional[PhotoSetReadinessReport] = None
    summary: Dict[str, Any] = field(default_factory=dict)
```

Ownership rules:

- `image_assessment.py` remains the owner of photo-quality and photo-set assessment DTOs.
- `collector_workspace.py` owns only workspace selection metadata and report presentation fields.
- Do not duplicate scoring logic, readiness rules, or downstream permission decisions in `CollectorWorkspace`.
- The wrapper exists to make the result fit existing workspace report patterns, not to create a second assessment model.

The DTO should provide `to_dict()` so `generate_report(...)` can serialize it consistently.

## 4. Engine Lifecycle

Add a lazy engine branch:

```python
elif name == "image_assessment":
    from image_assessment import ImageAssessmentEngine
    return ImageAssessmentEngine()
```

Rules:

- Create the engine only when `get_image_assessment(...)` is called.
- Reuse the same engine instance for the lifetime of the `CollectorWorkspace`.
- Do not instantiate the engine from the GUI.
- Do not pass collection data into the engine constructor.
- Do not add external dependencies or provider configuration.

## 5. Cache Strategy

Use workspace-session caching only.

Recommended cache key components:

- namespace: `image_assessment`
- selection type: `explicit_photos`, `item`, `candidate`, or `none`
- selection id: item id, candidate id, or empty string
- certified flag
- deterministic photo identity payload:
  - path
  - role
  - display order where available
  - primary flag where available

Example key shape:

```text
image_assessment:<sha256-digest>
```

Rules:

- Normalize paths for cache-key comparison only.
- Do not modify photo paths on the source objects.
- `refresh()` clears all image-assessment cache entries because it already clears the workspace cache.
- `refresh=True` should invalidate or bypass only the matching assessment key.
- Do not add filesystem modification-time tracking in this phase.
- Do not persist image-assessment cache to disk.

This keeps behavior deterministic and avoids turning Phase 2 into a file-monitoring system.

## 6. Error Handling

Errors should degrade into reports wherever possible.

Expected degraded cases:

- unknown `item_id`
- unknown `candidate_id`
- selected item has no photos
- selected candidate has no assessable photo references
- missing image files
- unreadable or corrupt image files
- malformed photo role metadata
- engine exception for one photo

Rules:

- A bad image must not prevent a complete set report from being returned.
- Workspace selection errors belong in `ImageAssessmentReport.engine_errors`.
- Image/file errors discovered by the engine remain in `PhotoQualityAssessment.engine_errors` or `PhotoSetReadinessReport.engine_errors`.
- Do not show message boxes or other GUI notifications in this phase.
- Do not mutate collection items, photo records, or candidates while handling errors.

## 7. Reports Panel Behavior

Add a `ReportDescriptor` entry only if the implementation can generate a meaningful report without a GUI selection.

Recommended descriptor:

```python
ReportDescriptor(
    name="image_assessment",
    title="Image Assessment Readiness",
    category="Photo",
    description="Deterministic photo-quality and downstream-readiness assessment",
    engine_name="image_assessment",
    method_name="assess_photos",
    has_markdown_export=True,
    has_csv_export=False,
    available=True,
)
```

Because `generate_report(name)` has no way to pass a selected item today, the report-panel default should be conservative:

- assess all collection items with photos only if that can be summarized without expensive or surprising behavior, or
- return a no-selection report explaining that an item, candidate, or explicit photo set is required.

Preferred Phase 2 behavior:

- Add the descriptor so the capability is discoverable.
- `generate_report("image_assessment")` returns a no-selection/degraded report unless a later GUI supplies a selection through `get_image_assessment(...)`.
- Do not add a new workspace tab or visible GUI panel in this phase.

Future GUI integration can call `get_image_assessment(item_id=...)` directly for selected items.

## 8. Markdown and Export Decision

Markdown is useful for this report because the output is explanation-heavy:

- downstream readiness by task
- blocking issues
- evidence
- recommended corrective actions
- individual photo findings

Recommended Phase 2 implementation:

- Add `ImageAssessmentReport.export_markdown(path)` or `ImageAssessmentReport.to_markdown()` plus a thin export wrapper.
- Do not add CSV export in this phase.
- Do not add file attachments or image thumbnails to the export.
- Do not export raw image metrics unless already present in the DTO and useful for debugging.

Reports Panel descriptor should set:

```python
has_markdown_export=True
has_csv_export=False
```

If implementation finds that report export requires an awkward special case, markdown export may be deferred, but the design preference is to support markdown because it matches the explanatory purpose of the assessment layer.

## 9. Test Plan

Add focused workspace tests, likely in `test_collector_workspace_image_assessment.py`.

Required tests:

- `get_image_assessment()` with no selection returns a degraded report.
- explicit photo list is assessed.
- explicit photos take precedence over `item_id`.
- item selection finds the correct collection item.
- unknown item id returns a degraded report.

- no collection item or photo object is mutated.
- `generate_report("image_assessment")` returns a serializable dict.
- Reports Panel descriptor includes Image Assessment.
- markdown export succeeds if implemented.
- full `python -m unittest discover` passes.

Use small generated temporary images in tests, following the Phase 1 image-assessment test style.

## 11. Regression Risks

Primary risks:

- accidentally duplicating image-readiness rules in `CollectorWorkspace`
- making the report-panel path perform broad expensive image scans by default
- stale cache results after photo edits
- mutating `CoinItem.photos` while building assessment inputs
- treating Image Assessment as grading readiness instead of photo readiness
- exposing a GUI surface before the workspace API is stable
- staging unrelated debug image deletions or personal data files
- coupling this phase to Canadian Reference Intelligence or catalogue providers

Mitigations:

- keep all scoring and readiness decisions inside `ImageAssessmentEngine`
- use explicit cache invalidation through `refresh()` and `refresh=True`
- default report-panel generation to a degraded/no-selection report unless a safe aggregate is implemented
- test no-mutation behavior directly
- keep implementation commit scope narrow

1. Add `ImageAssessmentReport` to `collector_workspace.py`.
2. Add lazy `_create_engine("image_assessment")`.
3. Add selection helpers for explicit photos, item id, and candidate id.
4. Add deterministic cache-key helper.
5. Add `get_image_assessment(...)`.
6. Add `to_dict()` and markdown export support if consistent with existing report export behavior.
7. Add the Reports Panel descriptor.
8. Add focused workspace tests.
9. Run `python -m unittest test_collector_workspace_image_assessment.py`.
10. Run `python -m unittest discover`.

Stop after workspace integration. Do not begin GUI, Canadian Reference Intelligence, or grading-readiness work.
