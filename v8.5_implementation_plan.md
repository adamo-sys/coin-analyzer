## Phase 1 — Advisor Core Engine (Design → Review → Approval → Implement)

### Scope
Design and implement `CollectorAdvisor` — the thin recommendation orchestrator.

**Phase 1 includes ONLY:**
- `collector_advisor.py` module
- `CollectorRecommendation`, `RecommendationReason`, `AdvisorReport` DTOs
- `CollectorAdvisor` class with all `recommend_*()` methods
- `generate_advisory_report()`
- `test_collector_advisor.py` unit tests

**Phase 1 does NOT include:**
- GUI integration (no `coin_collection_gui.py` changes)
- Smart Shopping modifications
- Connected Data modifications
- Collector Workspace modifications
- Report export (Markdown/CSV)
- Any changes to existing engines

### Public API
```python
class CollectorAdvisor:
    def __init__(self, workspace: CollectorWorkspace)
    def generate_advisory_report(self) -> AdvisorReport
    def recommend_priority_acquisitions(self) -> List[CollectorRecommendation]
    def recommend_grade_submissions(self) -> List[CollectorRecommendation]
    def recommend_upgrades(self) -> List[CollectorRecommendation]
    def recommend_duplicate_disposal(self) -> List[CollectorRecommendation]
    def recommend_budget_allocation(self) -> List[CollectorRecommendation]
    def recommend_next_action(self) -> Optional[CollectorRecommendation]
```

### DTO Ownership
- `CollectorAdvisor` owns: `CollectorRecommendation`, `RecommendationReason`, `AdvisorReport`
- Everything else is borrowed from existing engine outputs

### Constraints
- No new intelligence engine
- No new persistence layer
- No duplicated business logic
- Every recommendation must include non-empty evidence
- Deterministic, testable, explainable
- **Given identical inputs and configuration, must always produce identical recommendation ordering and evidence**

### Success Criteria
| # | Criterion | How Verified |

| 1 | One new module (`collector_advisor.py`) | File count |

| 3 | Stable public API | Signature tests |
| 4 | Deterministic recommendation ordering | Same input → same output test |
| 5 | Evidence attached to every recommendation | Assert `len(rec.evidence) > 0` in all tests |

## Phase 2 — Workspace Integration

### Scope
Add `get_advisor()` to `CollectorWorkspace` with lazy engine initialization.

### Design Refinements (from Phase 1 review)
1. **Workspace-only constraint:** `CollectorAdvisor` must consume only workspace DTOs (`get_dashboard`, `get_opportunities`, `get_want_list`, etc.). No direct engine imports or calls. The workspace remains the sole integration point.
2. **RecommendationCategory enum:** Introduce `RecommendationCategory(Enum)` to replace string `recommendation_type`. This is a forward-compatible change — the enum values map directly to the existing string constants, and the public API gains type safety without breaking existing callers.

### Enum Design
```python
from enum import Enum

class RecommendationCategory(Enum):
    PRIORITY_ACQUISITION = "PRIORITY_ACQUISITION"
    GRADE_SUBMIT = "GRADE_SUBMIT"
    UPGRADE = "UPGRADE"
    DISPOSE_DUPLICATE = "DISPOSE_DUPLICATE"
    BUDGET_ALLOCATE = "BUDGET_ALLOCATE"
    NEXT_ACTION = "NEXT_ACTION"
```

### Phase 2 Deliverables
- Update `CollectorRecommendation.recommendation_type: str` → `recommendation_type: RecommendationCategory`
- Update all `recommend_*()` methods to use enum values
- Update `test_collector_advisor.py` to use enum in assertions
- Add `get_advisor()` to `CollectorWorkspace`
- In-memory cache for advisor report
- Error resilience (graceful degradation if engines fail)
- Integration tests

### Constraints
- Keyword-only parameters for any new arguments
- Existing workspace panels unchanged
- All new methods use lazy initialization pattern
- No direct engine calls from Advisor (workspace DTOs only)
- Enum change is backward-compatible (enum values are strings)

### Workspace Integration API
```python
class CollectorWorkspace:
    # ... existing 10 panels + Connected Data ...

    def get_advisor(self) -> AdvisorReport:
        """Generate advisory recommendations from all engines.
        
        Lazy initialization: CollectorAdvisor is created on first call.
        Cached: result is stored in _cache and returned on subsequent calls.
        """
```

## Permanent Rules (v8.5+)

1. **CollectorAdvisor is a recommendation layer, not an intelligence engine.** All analysis stays in existing engines. The Advisor only orchestrates and explains.
2. **Every recommendation must be explainable.** Every recommendation DTO includes `evidence: List[str]` with human-readable reasons.
3. **CollectorAdvisor must be deterministic.** Given identical inputs and configuration, it must always produce identical recommendation ordering and evidence.
4. **No new intelligence engine.** No ML, no LLM, no black box. Deterministic logic only.
5. **Advisory only.** The collector decides. The software explains.
