MISSION
=======

Build the Collection Assistant.

The purpose of this release is not to add more intelligence.

The purpose is to dramatically reduce the amount of manual work required to catalogue coins.

Everything should build on the existing engines.

No duplicate business logic.

No replacement of existing workflows.

PHASE 12
ARCHITECTURAL PRINCIPLES
========================

Maintain a clean, modular architecture.

Whenever possible:

* Extend existing engines instead of creating duplicate functionality.
* Reuse existing modules before introducing new ones.
* New modules should orchestrate existing capabilities rather than reimplement business logic.
* Avoid duplicate calculations, duplicate data models, and duplicate export logic.
* Keep deterministic behavior centralized within the appropriate engine.
* Preserve backwards compatibility whenever practical.
* Prefer composition over duplication.
* If functionality already exists elsewhere, call or extend it rather than copying its logic.

This release should improve workflow efficiency—not create parallel implementations.

DEFINITION OF DONE
==================

The Collection Assistant becomes the primary cataloguing workflow for the application.

It reduces manual effort by orchestrating the existing Photo Capture, OCR Identification, Collection Intelligence, Collection Insights, and Acquisition Strategy engines into a single guided review experience.

Target outcome:

Reduce manual cataloguing time by approximately 50% while preserving user review and approval for every collection change.

This establishes the productivity foundation for:

v7.5 = Numista Intelligence

where the assistant begins automatically proposing high-confidence Numista matches to accelerate identification even further.
