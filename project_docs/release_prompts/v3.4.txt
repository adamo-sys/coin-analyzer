## GOAL

Transform Deal Hunter from:

"Evaluate one listing"

into:

"Rank large pools of candidate listings and surface the best opportunities."

This release focuses on:

* ranking
* prioritization
* budget allocation
* import scalability

Do NOT add:

* scraping
* browser automation
* eBay APIs
* live listing retrieval
* live pricing
* image recognition
* automatic purchasing
* collection mutation

Deterministic local logic only.

---

1. CANDIDATE POOL SYSTEM

---

Create:

CandidatePool

Purpose:

Store and manage large groups of imported listings.

Support:

* manual entries
* existing Deal Hunter CSV imports
* multiple CSV imports merged together

CandidatePool should preserve:

* source
* seller
* URL
* parsed metadata
* scores
* recommendations

2. DEAL HUNTER RANKING ENGINE

---

Create:

DealHunterRankingEngine

Purpose:

Rank candidate listings by overall opportunity.

Use:

* Deal Hunter scores
* Opportunity Engine scores
* Collection fit
* Upgrade value
* Gap filling value
* Want-list relevance
* Liquidity
* Risk
* Budget fit

Output:

RankingScore

0–100

Deterministic.

5. IMPORT FRAMEWORK

---

Create:

ImportProfile

Support:

* eBay CSV
* Auction CSV
* Dealer CSV
* Custom CSV

This is a framework only.

Do NOT implement scraping.

Do NOT implement APIs.

Do NOT fetch listings.

Purpose:

Allow future connectors to plug into a common structure.

---

6. IMPORT VALIDATION

---

Validate:

* required fields
* pricing
* URLs
* duplicate imports
* malformed rows
* unsupported formats

Generate import warnings.

Do not silently discard records.

---

7. DUPLICATE MANAGEMENT

---

Detect:

* identical URLs
* duplicate listings
* repeated imports

Allow ranking engine to avoid duplicate recommendations.

---

8. OPPORTUNITY CONSOLIDATION

---

If multiple listings represent:

* same upgrade
* same want-list target
* same collection gap

Consolidate opportunity reporting where appropriate.

Avoid flooding reports.
