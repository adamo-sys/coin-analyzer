Begin v3.7 development.

Roadmap Context:

v3.5 = External Listing Connectors
v3.6 = Deal Hunter Calibration
v3.7 = Live Deal Hunter Readiness
v4.0 = Live Deal Hunter

GOAL:

Prepare the system for future live listing ingestion without adding live ingestion yet.

This is a readiness, safety, and architecture release.

Do NOT add:

* scraping
* browser automation
* eBay API calls
* dealer API calls
* auction API calls
* live listing retrieval
* automatic purchasing
* automatic collection mutation
* live pricing claims

---

1. LIVE SOURCE READINESS AUDIT

---

Create:

LiveDealHunterReadinessAudit

Purpose:

Evaluate whether the current offline Deal Hunter stack is ready for live sources.

Check:

* connector framework readiness
* ranking readiness
* calibration readiness
* duplicate detection readiness
* source validation readiness
* rate-limit safety planning
* failure handling
* no-collection-mutation safety

Output:

LiveDealHunterReadinessReport

---

2. LIVE SOURCE CONTRACTS

---

Create interface-style contracts only.

Examples:

LiveListingSource
LiveListingBatch
LiveListingFetchResult

Do not implement real fetching.

The contracts should define what future live sources must provide:

* title
* price
* shipping
* currency
* seller
* URL
* image URL
* source name
* fetched timestamp
* listing end time
* raw metadata

---

3. SAFETY RULES

---

Document and enforce future live-ingestion safety expectations:

* no automatic purchasing
* no automatic collection mutation
* no hidden network calls
* explicit user-triggered fetch only
* source-specific rate-limit awareness
* clear failure reporting
* stale listing warnings
* currency validation required
* shipping included in total cost

---

4. SOURCE VALIDATION PLANNING

---

Create:

LiveSourceValidationReport

Validate future source outputs for:

* missing price
* missing shipping
* non-CAD currency
* stale listing
* duplicate URL
* malformed URL
* missing seller
* missing title
* suspicious metadata

---

5. STALENESS MODEL

---

Create deterministic staleness flags:

* FRESH
* STALE
* UNKNOWN

Do not fetch live data.

Use supplied timestamps only.

---

6. RATE LIMIT PLAN

---

Create:

RateLimitPolicy

Document:

* source name
* allowed fetch cadence
* batch size guidance
* retry guidance
* cooldown guidance

No actual scheduling or background fetch.

---

7. FAILURE HANDLING PLAN

---

Define:

LiveSourceFailure

Examples:

* network unavailable
* source unavailable
* authentication required
* malformed response
* rate limited
* unsupported source

No live calls.

Models and reports only.
