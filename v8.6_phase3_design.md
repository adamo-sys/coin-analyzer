# v8.6 Phase 3 Design - Workflow Explainability & Navigation

Status: DESIGN ONLY. Awaiting approval before implementation.

## Mission

Improve unified workflow output so it clearly answers:

1. Why is this workflow `READY`, `NEEDS_INPUT`, `REVIEW_REQUIRED`, `BLOCKED`, or `COMPLETE`?
2. What evidence supports that state?
3. What should the collector do next?
4. Which existing tool should the collector open?

Phase 3 is metadata only. It may add descriptive fields that identify a recommended tool, but it must not add GUI launch logic, callbacks, command execution, routing hooks, persistence, or new workflow behavior.

## 1. Public API Changes

Keep the existing Phase 1/2 APIs:

```python
CollectorWorkflowEngine.run_workflow(request) -> UnifiedWorkflowReport
CollectorWorkspace.get_workflows() -> UnifiedWorkflowReport
CollectorWorkspace.get_workflow(request) -> UnifiedWorkflowReport
```

Recommended additive API surface:

```python
UnifiedWorkflowReport.state_reason: str
UnifiedWorkflowReport.recommended_tool: RecommendedTool
UnifiedWorkflowReport.recommended_tool_label: str

WorkflowAction.recommended_tool: RecommendedTool
WorkflowAction.recommended_tool_label: str
```

These fields are metadata only. They identify the existing tool a collector should open manually or a future GUI may display. They do not execute anything. `RecommendedTool` is a constrained enum so workflow reports do not depend on scattered free-form strings.

No new public workflow methods are needed.

## 2. DTO Changes

### UnifiedWorkflowReport

Add:

```python
state_reason: str = ""
recommended_tool: RecommendedTool = RecommendedTool.NONE
recommended_tool_label: str = ""
```

Meaning:

- `state_reason`: short human-readable explanation for the workflow state.
- `recommended_tool`: stable enum value.
- `recommended_tool_label`: display label for that tool.

Example:

```python
UnifiedWorkflowReport(
    workflow_type=WorkflowType.DUPLICATE_REVIEW,
    state=WorkflowState.REVIEW_REQUIRED,
    title="Duplicate Review",
    summary="2 duplicate groups need review",
    state_reason="Duplicate groups were found and require collector review before any action.",
    recommended_tool="collection_intelligence",
    recommended_tool_label="Collection Gap Report",
)
```

### WorkflowAction

Add:

```python
recommended_tool: RecommendedTool = RecommendedTool.NONE
recommended_tool_label: str = ""
```

Meaning:

- Action-level navigation metadata when a specific next action points to a better tool than the overall report.
- For example, a Daily Inbox report may have one action pointing to OCR and another pointing to Photo Vault.

### WorkflowEvidence

No required DTO change.

Existing fields already support source-labeled evidence:

- `source`
- `detail`
- `severity`
- `action`

If implementation needs more clarity, prefer improving `detail` and `action` text before adding fields.

## 3. State Explanation Model

Each `UnifiedWorkflowReport` should include a `state_reason`.

Recommended state reason rules:

| State | Explanation Pattern |
| --- | --- |
| `READY` | Analysis completed and the workflow has reviewable output. |
| `NEEDS_INPUT` | Required input is missing; name what is needed. |
| `REVIEW_REQUIRED` | Evidence includes warnings, duplicates, low trust, conflicts, or manual decisions. |
| `BLOCKED` | A source engine failed or the request could not be processed. |
| `COMPLETE` | No immediate action was detected from available data. |

Examples:

- `READY`: "Daily Inbox generated reviewable workflow tasks from current workspace data."
- `NEEDS_INPUT`: "Acquisition Review requires a candidate before workflow evidence can be generated."
- `REVIEW_REQUIRED`: "Duplicate holdings were detected and need collector review before any action."
- `BLOCKED`: "CollectorWorkspace could not retrieve a workflow report because the workflow engine failed."
- `COMPLETE`: "No duplicate groups were detected from the current collection data."

The reason should be deterministic and derived from workflow state, warnings, evidence, and route type.

## 4. Evidence Model

Keep evidence source-labeled and action-oriented.

Evidence should answer:

- Which engine produced this signal?
- What did it find?
- How serious is it?
- What manual review action does it support?

Recommended evidence quality rules:

1. Every workflow report should have at least one evidence item.
2. Every workflow action should have at least one evidence item.
3. Evidence `source` should name the owning engine or layer, not a generic phrase.
4. Evidence `detail` should be human-readable.
5. Evidence `action` should describe review intent, not execute behavior.
6. Warning/error evidence should influence `state_reason`.

No new recommendation categories should be introduced.

## 5. Tool Navigation Model

Navigation is metadata only.

Add a small internal mapping in `collector_workflows.py`, not GUI code:

```python
WORKFLOW_TOOL_MAP = {
    WorkflowType.ACQUISITION_REVIEW: ("smart_shopping_assistant", "Smart Shopping Assistant"),
    WorkflowType.COLLECTION_REVIEW: ("collection_dashboard", "Collection Dashboard"),
    WorkflowType.UPGRADE_REVIEW: ("upgrade_advisor", "Upgrade Advisor"),
    WorkflowType.DUPLICATE_REVIEW: ("collection_intelligence", "Collection Gap Report"),
    WorkflowType.DAILY_INBOX: ("collector_workspace", "Collector Workspace"),
}
```

Action-level overrides may use existing tool keys such as:

| Situation | Tool Key | Label |
| --- | --- | --- |
| OCR warnings | `ocr_experiment` | OCR Experiment |
| Photo issues | `photo_vault` | Photo Vault |
| Data integrity warnings | `collection_integrity` | Collection Integrity Report |
| Shopping opportunity | `smart_shopping_assistant` | Smart Shopping Assistant |
| Duplicate review | `collection_intelligence` | Collection Gap Report |
| Upgrade review | `upgrade_advisor` | Upgrade Advisor |
| Daily overview | `collector_workspace` | Collector Workspace |

Rules:

1. `recommended_tool` is a stable enum value only.
2. `recommended_tool_label` is display text only.
3. No callable, function name, Tkinter method name, menu command, URL, file path, shell command, or GUI launch behavior should be stored.
4. Future GUI may choose how to interpret these fields, but Phase 3 must not implement that.

## 6. Error and Fallback Behavior

The degraded behavior from Phase 1/2 remains:

- invalid workspace request -> `BLOCKED`
- source engine failure -> `BLOCKED`
- missing candidate/input -> `NEEDS_INPUT`
- empty data -> valid report with explanatory evidence

New Phase 3 expectations:

1. `BLOCKED` reports include `state_reason`.
2. `BLOCKED` reports recommend a safe metadata tool key such as `collector_workspace` or the workflow-specific source.
3. `NEEDS_INPUT` reports identify the missing input in `state_reason`.
4. Tool metadata falls back to workflow-level mapping if action-specific mapping is not known.
5. Tool metadata must never be required for correctness; missing labels should not crash report generation.

## 7. Test Plan

Add tests primarily in `test_collector_workflows.py`, with a smaller set in `test_collector_workspace.py` only if serialization/report export needs coverage.

### DTO Tests

- `UnifiedWorkflowReport.to_dict()` includes `state_reason`, `recommended_tool`, and `recommended_tool_label`.
- `WorkflowAction.to_dict()` includes action-level tool metadata.
- Existing DTO construction without the new fields remains valid.

### State Explanation Tests

- Acquisition missing candidate returns `NEEDS_INPUT` with a reason naming the candidate.
- Duplicate review with duplicates returns `REVIEW_REQUIRED` with duplicate-focused reason.
- Duplicate review with no duplicates returns `COMPLETE` with no-action reason.
- Source failure returns `BLOCKED` with failure reason.
- Daily Inbox returns `READY` or `REVIEW_REQUIRED` with a human-readable reason.

### Evidence Tests

- Every workflow report has evidence.
- Every workflow action has evidence.
- Evidence source names remain source-labeled.
- Warning/error evidence contributes to `state_reason`.

### Tool Metadata Tests

- Each workflow type gets report-level `recommended_tool` and `recommended_tool_label`.
- OCR-related Daily Inbox actions can recommend OCR metadata when OCR warnings exist.
- Photo-related actions can recommend Photo Vault metadata when photo issues exist.
- Duplicate actions recommend Collection Intelligence metadata.
- Upgrade actions recommend Upgrade Advisor metadata.
- No tool metadata contains callable values.

### Workspace Tests

- `CollectorWorkspace.get_workflows().to_dict()` preserves tool metadata.
- `generate_report("workflow_review")` includes tool metadata in serialized output.
- Markdown workflow export may mention recommended tool label as text only.

### Regression

- `python -m unittest test_collector_workflows.py`
- `python -m unittest test_collector_workspace.py`
- `python -m unittest discover`
