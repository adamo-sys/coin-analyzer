## Proposed Polish

Keep the markdown export simple, deterministic, and audit-friendly.

Recommended structure:

```markdown
# Workflow Review

## Status

- Workflow Type: DAILY_INBOX
- State: REVIEW_REQUIRED
- State Reason: Daily Inbox found workflow items that require collector review.
- Recommended Tool: Workflow Review
- Recommended Tool Key: WORKFLOW

## Summary

Daily collector priorities generated

## Next Actions

1. Review OCR items
   - State: REVIEW_REQUIRED
   - Reason: Daily collector priorities generated
   - Recommended Tool: OCR Experiment
   - Recommended Tool Key: OCR_EXPERIMENT
   - Evidence:
     - [WARNING] WorkflowStatus: OCR Pending: 1 OCR report(s) need review

## Evidence

- [WARNING] WorkflowStatus: OCR Pending: 1 OCR report(s) need review
  - Action: Review OCR validation reports

## Warnings

- OCR Pending: 1 OCR report(s) need review
```

Formatting rules:

- Include both tool label and enum key for auditability.
- Include action-level tool label and enum key.
- Include action-level evidence when present.
- Include evidence `action` text when present.
- Use numbered actions for readability.
- Use deterministic section order.
- Use stable empty-state text:
  - `No workflow actions available.`
  - `No workflow evidence available.`
  - `No workflow warnings.`
- Keep markdown text only; no embedded GUI instructions or links.

## Error and Fallback Behavior

The export path should preserve existing graceful degradation:

- `BLOCKED` workflow reports export normally.
- `NEEDS_INPUT` workflow reports export normally.
- Missing evidence/actions/warnings render empty-state text.
- Unknown or missing tool metadata renders `N/A` without raising.
- File write errors may continue to propagate as normal export errors.

No exceptions from workflow generation should escape through `get_workflows()`; that remains a CollectorWorkspace responsibility.
