## Phase 3 Enrichment Strategy

### Cross-Panel Evidence

Instead of each `recommend_*()` method consuming only one panel, Phase 3 consumes **multiple panels** and cross-references them for richer evidence:

```
recommend_priority_acquisitions()
  ├── get_want_list() ────────→ gap_targets, upgrade_candidates
  ├── get_opportunities() ────→ top_recommendations, highest_impact
  ├── get_connected_data() ───→ watchlist_matches, deal connections
  └── get_collection_summary() → series_completion, total_items

recommend_upgrades()
  ├── get_want_list() ────────→ upgrade_candidates
  ├── get_opportunities() ────→ highest_impact
  └── get_connected_data() ───→ photo links, market context

recommend_duplicate_disposal()
  ├── get_collection_summary() → total_items, series_completion
  ├── get_want_list() ────────→ (reverse check: items NOT in gaps)
  └── get_connected_data() ───→ duplicate references, photo links

recommend_grade_submissions()
  ├── get_ai_queue() ─────────→ ai_grading_review (count + items)
  ├── get_photo_vault() ──────→ coverage_percentage, certified_items
  └── get_collection_summary() → series_completion (which sets need grading)
```

### Evidence Quality Rules

Every `RecommendationReason` in Phase 3 must follow these rules:

1. **Specific, not generic.** "Missing 1910 Newfoundland 5¢" not "Collection gap target."
2. **Cross-referenced.** At least one evidence item must cite a second panel.
3. **Actionable.** Evidence should suggest what to do, not just describe what is.
4. **Impact-aware.** Include collection impact when available (quality delta, completion percentage, etc.).
5. **Source-labeled.** Every evidence item names its source engine.

### Example: Enriched Priority Acquisition

```python
CollectorRecommendation(
    recommendation_id="acq_gap_1",
    recommendation_type=RecommendationCategory.PRIORITY_ACQUISITION,
    title="Acquire 1910 Newfoundland 5¢",
    description="Missing date from Edward VII nickel set. No owned example. HIGH priority want-list gap.",
    evidence=[
        RecommendationReason(
            category="priority",
            description="Missing 1910 Newfoundland 5¢ from Edward VII nickel set. Owned dates: 1904, 1908, 1912. Set completion: 75%.",
            source_engine="collection_intelligence",
            confidence="HIGH",
        ),
        RecommendationReason(
            category="cross_reference",
            description="Connected Data confirms this gap appears in both want-list AND opportunity rankings.",
            source_engine="connected_data",
            confidence="HIGH",
        ),
        RecommendationReason(
            category="impact",
            description="Acquisition would increase series completion from 75% to 100%. Quality score impact: +3 points.",
            source_engine="acquisition_impact",
            confidence="MEDIUM",
        ),
    ],
    priority="HIGH",
    urgency="SHORT_TERM",
    related_items=["gap_1", "1910_newfoundland_5c"],
)
```

## DTO Changes

**None.** Phase 3 uses existing DTOs. No new fields, no new dataclasses.

The enrichment is entirely in the **quality of evidence descriptions** and the **cross-referencing of multiple panels** within each `recommend_*()` method.

## Deterministic Ordering Rules

**Unchanged from Phase 2.** The sort key remains:

```python
_PRIORITY_ORDER = {"HIGH": 0, "MEDIUM": 1, "LOW": 2}
_URGENCY_ORDER = {"IMMEDIATE": 0, "SHORT_TERM": 1, "LONG_TERM": 2, "ONGOING": 3}

def _priority_sort_key(rec: CollectorRecommendation) -> Tuple[int, int, str]:
    return (
        _PRIORITY_ORDER.get(rec.priority, 1),
        _URGENCY_ORDER.get(rec.urgency, 3),
        rec.recommendation_id,
    )
```

Phase 3 may change the **priority** assigned to specific recommendations (e.g., a cross-referenced gap gets upgraded from MEDIUM to HIGH), but the sort mechanism itself is stable.

---

## Error / Fallback Behavior

**Unchanged from Phase 2.** Each `recommend_*()` method catches its own exceptions and continues:

```python
try:
    want_list = self.workspace.get_want_list()
except Exception:
    want_list = None
```

If a panel needed for cross-referencing is missing, the method falls back to single-panel evidence. The recommendation still has evidence, but the cross-reference is omitted.

Example fallback:
- Full: "Connected Data confirms this gap appears in both want-list AND opportunities."
- Fallback: "Want-list gap identified. (Connected Data panel unavailable for cross-reference.)"

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Evidence becomes too verbose | Medium | Low | Keep evidence descriptions under 120 characters; use `evidence_summary` for display, not raw evidence list |
| Cross-referencing introduces subtle ordering changes | Medium | High | Determinism test catches any ordering drift; sort key is unchanged |
| Fallback evidence is too thin | Low | Medium | Every recommendation still has ≥2 evidence items even with single panel |
| Related items become stale | Low | Low | `related_items` contains IDs from workspace DTOs, not computed IDs |
