## Phase 1 - Workflow Engine

Status: COMPLETE

Create one workflow engine/facade that supports Acquisition Review, Collection Review, Upgrade Review, Duplicate Review, and Daily Inbox.

### Public API Target

```python
class WorkflowType(Enum):
    ACQUISITION_REVIEW = "ACQUISITION_REVIEW"
    COLLECTION_REVIEW = "COLLECTION_REVIEW"
    UPGRADE_REVIEW = "UPGRADE_REVIEW"
    DUPLICATE_REVIEW = "DUPLICATE_REVIEW"
    DAILY_INBOX = "DAILY_INBOX"

@dataclass
class WorkflowRequest:
    workflow_type: WorkflowType
    candidate: Optional[Any] = None
    collection_items: Sequence[Any] = field(default_factory=list)
    want_list: Sequence[Any] = field(default_factory=list)
    context: Dict[str, Any] = field(default_factory=dict)

@dataclass
class WorkflowEvidence:
    source: str
    detail: str
    severity: str = "INFO"

@dataclass
class UnifiedWorkflowReport:
    workflow_type: WorkflowType
    title: str
    status: str
    summary: str
    evidence: List[WorkflowEvidence]
    next_actions: List[str]
    warnings: List[str]
    source_reports: Dict[str, Any]

class CollectorWorkflowEngine:
    def run_workflow(self, request: WorkflowRequest) -> UnifiedWorkflowReport:
        ...
```

The names may change during implementation if existing code strongly suggests a better local pattern, but the single-entry-point requirement should remain.

### Workflow Coverage

Acquisition Review:
- Candidate purchase or listing review.
- Reuses acquisition workflow, Smart Shopping, Advisor, market awareness, and collection intelligence.

Collection Review:
- Collection state review.
- Reuses collection dashboard, quality, integrity, snapshot, and portfolio performance.

Upgrade Review:
- Existing item versus possible replacement.
- Reuses Upgrade Advisor and collection intelligence.

Duplicate Review:
- Duplicate and lower-grade duplicate review.
- Reuses collection intelligence, collection integrity, and advisor evidence.

Daily Inbox:
- New purchases, OCR items, photo items, shopping candidates, and unresolved review tasks.
- Reuses workspace inbox, workflow status, photo vault, OCR, and persistence context where available.

### Constraints

- No collection mutation.
- No automatic purchase, bid, sale, grade submission, deletion, or conflict resolution.
- No live scraping or new external API dependency.
- No new persistence in Phase 1.
- No GUI work in Phase 1 unless explicitly approved after API stabilization.
- Preserve existing public APIs unless a breaking change is documented and approved.

### Tests

- Unit tests for each workflow type.
- Deterministic ordering tests.
- Empty input tests.
- Missing engine / degraded data tests.
- Evidence non-empty tests for every non-empty report.
- Export formatting tests only if export is touched.
