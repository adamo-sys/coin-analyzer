# v8.6 Phase 2 Design - Workflow Workspace Integration

Status: APPROVED AND IMPLEMENTED.

## 1. Mission

Expose the Phase 1 Unified Workflow Engine through `CollectorWorkspace` so the rest of the application has one ViewModel entry point for workflow review.

Phase 2 is deliberately small:

- No GUI
- No new workflow logic
- No new workflow DTOs
- No new intelligence
- No persistence
- No collection mutation
- No Advisor or Connected Data changes

The workspace should only route requests to `CollectorWorkflowEngine.run_workflow()` and cache/report the normalized `UnifiedWorkflowReport`.

## 2. Public API

Add two methods to `CollectorWorkspace`:

```python
def get_workflows(self) -> UnifiedWorkflowReport:
    """Return the default workflow dashboard/inbox summary."""

def get_workflow(self, request: WorkflowRequest) -> UnifiedWorkflowReport:
    """Run one selected workflow through the unified workflow engine."""
```

Recommended default behavior:

```python
get_workflows()
```

should call:

```python
get_workflow(WorkflowRequest(WorkflowType.DAILY_INBOX))
```

Rationale:

- `get_workflows()` mirrors existing panel-style workspace getters.
- `get_workflow(request)` exposes the Phase 1 selection API.
- The workspace remains a ViewModel and does not duplicate workflow routing logic.

## 3. DTO Design

No new DTOs.

Reuse from `collector_workflows.py`:

- `WorkflowRequest`
- `WorkflowType`
- `WorkflowState`
- `WorkflowEvidence`
- `WorkflowAction`
- `UnifiedWorkflowReport`

`CollectorWorkspace` should not wrap these in workspace-specific workflow DTOs during Phase 2.

## 4. Data Flow

```text
CollectorWorkspace.get_workflows()
        |
        v
CollectorWorkspace.get_workflow(WorkflowRequest(DAILY_INBOX))
        |
        v
_get_engine("collector_workflows")
        |
        v
CollectorWorkflowEngine.run_workflow(request)
        |
        v
UnifiedWorkflowReport
```

For selected workflows:

```text
CollectorWorkspace.get_workflow(request)
        |
        v
CollectorWorkflowEngine.run_workflow(request)
        |
        v
UnifiedWorkflowReport
```

The workspace only delegates. It must not inspect collection items to build workflow logic.

## 5. Cache Design

Follow existing workspace cache patterns:

```python
if "workflows" in self._cache:
    return self._cache["workflows"]
```

Default summary cache key:

```text
workflows
```

Selected workflow cache key:

```text
workflow:<workflow_type>
```

Only cache selected workflows when the request has no candidate, no owned item, no raw OCR text, and no context. Candidate-specific requests should run fresh because generic hashing would be brittle and could accidentally reuse the wrong review result.

`refresh()` already clears `_cache`, so no new refresh behavior is required.

Engine lifecycle:

```text
_get_engine("collector_workflows")
```

uses the existing lazy factory. No new constructor arguments are needed unless tests reveal Phase 1 context is missing.

## 6. Report Descriptor

Add one report descriptor:

```text
name: workflow_review
title: Workflow Review
category: Workflow
engine_name: collector_workflows
method_name: run_workflow
markdown export: true
csv export: false
```

Because `run_workflow()` requires a request, `_invoke_report_method()` should special-case this descriptor and call the workspace default:

```python
self.get_workflows()
```

Markdown-only export:

- Preferred: add `format_markdown()` / `export_markdown()` to `UnifiedWorkflowReport` only if needed for report export.
- Do not add CSV export in Phase 2.
- Do not redesign report export.

If adding export support to `UnifiedWorkflowReport` feels larger than expected, keep descriptor generation working and defer export until explicitly approved. The Phase 2 target is workspace integration, not export framework work.

## 7. Error Handling

Use the existing workspace pattern: never throw source engine failures into the GUI-facing layer.

Rules:

1. Invalid `WorkflowRequest` passed to `get_workflow()` should return a `BLOCKED` `UnifiedWorkflowReport`, not raise.
2. Engine failure should return a `BLOCKED` `UnifiedWorkflowReport`.
3. Missing workflow input should flow through Phase 1 and return `NEEDS_INPUT`.
4. `get_workflows()` should never raise during normal GUI/panel access.
5. Error evidence should be source-labeled as `CollectorWorkspace` or `CollectorWorkflowEngine`.

Suggested helper:

```python
def _blocked_workflow_report(self, detail: str) -> UnifiedWorkflowReport:
    ...
```

Do not create a new workspace-specific error DTO.

## 8. Ownership Boundaries

### `collector_workspace.py`

Owns:

- `get_workflows()`
- `get_workflow(request)`
- cache keys
- lazy access to `"collector_workflows"`
- report descriptor registration
- workspace-level failure wrapping

Does not own:

- workflow route logic
- workflow state decisions
- workflow evidence generation
- workflow action generation

### `collector_workflows.py`

Owns all workflow behavior through Phase 1 DTOs and `CollectorWorkflowEngine.run_workflow()`.

### GUI

No changes.

### Persistence

No changes.

## 9. Test Plan

Expected new tests in `test_collector_workspace.py`: about 10-15.

### Workspace API

- `get_workflows()` returns a `UnifiedWorkflowReport`.
- `get_workflows()` defaults to `WorkflowType.DAILY_INBOX`.
- `get_workflow(request)` returns the selected workflow report.
- `get_workflow()` passes the request to `CollectorWorkflowEngine.run_workflow()`.

### Lazy Engine and Cache

- `get_workflows()` lazily creates `"collector_workflows"`.
- `get_workflows()` caches under `"workflows"`.
- `refresh()` clears workflow cache.
- Candidate-specific `get_workflow(request)` does not reuse the default cache.
- Cache does not create a second workflow engine.

### Error and Degraded Reports

- `get_workflow()` with missing acquisition candidate returns `NEEDS_INPUT`.
- Source engine exception returns `BLOCKED`.
- Invalid request returns `BLOCKED`.
- Blocked reports include evidence and warnings.

### Report Menu

- `get_reports()` includes `workflow_review`.
- `workflow_review` has category `Workflow`.
- `workflow_review` is markdown-only.
- `generate_report("workflow_review")` serializes the default workflow report.

### Determinism

- Two calls to `get_workflow(WorkflowRequest(WorkflowType.DUPLICATE_REVIEW))` with identical state produce identical serialized output.
