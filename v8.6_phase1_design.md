# v8.6 Phase 1 Design - Workflow Engine

Status: DESIGN ONLY. Awaiting approval before implementation.

## 1. Mission

Create one unified workflow engine entry point that turns existing Coin Analyzer engines into reviewable collector workflows.

Phase 1 focuses only on:

- Acquisition Review
- Collection Review
- Upgrade Review
- Duplicate Review
- Daily Inbox

The engine should make the collector's next review step obvious while preserving the project's rules: deterministic output, source-labeled evidence, no collection mutation, no GUI work, no persistence, no external APIs, no scraping, no ML/CV, and no new recommendation categories.

The central design move is to extend the existing `collector_workflows.py` facade with a typed `run_workflow()` API and a normalized report model. Existing workflow-specific report DTOs remain valid source reports.

## 2. Public API

Phase 1 should add one primary public entry point to `CollectorWorkflowEngine`:

```python
class CollectorWorkflowEngine:
    def run_workflow(self, request: WorkflowRequest) -> UnifiedWorkflowReport:
        """Run one deterministic review workflow and return a normalized report."""
```

Recommended supporting API:

```python
class WorkflowType(Enum):
    ACQUISITION_REVIEW = "ACQUISITION_REVIEW"
    COLLECTION_REVIEW = "COLLECTION_REVIEW"
    UPGRADE_REVIEW = "UPGRADE_REVIEW"
    DUPLICATE_REVIEW = "DUPLICATE_REVIEW"
    DAILY_INBOX = "DAILY_INBOX"


class WorkflowState(Enum):
    READY = "READY"
    NEEDS_INPUT = "NEEDS_INPUT"
    REVIEW_REQUIRED = "REVIEW_REQUIRED"
    BLOCKED = "BLOCKED"
    COMPLETE = "COMPLETE"


class WorkflowSeverity(Enum):
    INFO = "INFO"
    WARNING = "WARNING"
    ERROR = "ERROR"
```

Optional convenience methods may remain or be added only as thin wrappers around `run_workflow()`:

```python
def acquisition_review(self, candidate: Any, *, raw_ocr_text: str = "") -> UnifiedWorkflowReport
def collection_review(self) -> UnifiedWorkflowReport
def upgrade_review(self, candidate: Any = None, *, owned_item: Any = None) -> UnifiedWorkflowReport
def duplicate_review(self) -> UnifiedWorkflowReport
def daily_inbox(self) -> UnifiedWorkflowReport
```

The single-entry-point contract is the important part. Convenience methods should not become separate logic paths.

## 3. DTO Design

### WorkflowRequest

```python
@dataclass
class WorkflowRequest:
    workflow_type: WorkflowType
    candidate: Optional[Any] = None
    owned_item: Optional[Any] = None
    raw_ocr_text: str = ""
    context: Dict[str, Any] = field(default_factory=dict)
```

Rationale:

- `workflow_type` selects the route.
- `candidate` supports acquisition and upgrade review.
- `owned_item` supports upgrade comparisons without changing collection records.
- `raw_ocr_text` preserves existing acquisition workflow behavior.
- `context` is read-only supplemental data for future extension without changing the method signature.

Collection items, want-list intents, photo records, shopping candidates, OCR reports, market awareness, and snapshot manager should continue to be injected through `CollectorWorkflowEngine.__init__()` as they are today.

### WorkflowEvidence

```python
@dataclass
class WorkflowEvidence:
    source: str
    detail: str
    severity: WorkflowSeverity = WorkflowSeverity.INFO
    action: str = ""
```

Rationale:

- Mirrors existing `WorkflowStatus` fields.
- Keeps source ownership explicit.
- Does not introduce new recommendation categories.

### WorkflowAction

```python
@dataclass
class WorkflowAction:
    label: str
    reason: str = ""
    source: str = ""
    state: WorkflowState = WorkflowState.REVIEW_REQUIRED
```

Rationale:

- Separates "what to do next" from evidence.
- Keeps all actions advisory and review-only.

### UnifiedWorkflowReport

```python
@dataclass
class UnifiedWorkflowReport:
    workflow_type: WorkflowType
    state: WorkflowState
    title: str
    summary: str
    evidence: List[WorkflowEvidence] = field(default_factory=list)
    next_actions: List[WorkflowAction] = field(default_factory=list)
    warnings: List[str] = field(default_factory=list)
    source_reports: Dict[str, Any] = field(default_factory=dict)
```

Rationale:

- Normalizes existing workflow outputs without deleting or reshaping their original DTOs.
- `source_reports` references existing reports such as `AcquisitionWorkflowReport`, `CollectionReviewReport`, `CollectorDailySummary`, advisor reports, quality reports, and integrity reports.
- The normalized report becomes the stable Phase 1 return type.

### Existing DTOs to Preserve

Do not remove or rename:

- `WorkflowStatus`
- `WorkflowSummary`
- `AcquisitionWorkflowReport`
- `CollectionReviewReport`
- `PhotoWorkflowReport`
- `CollectorDailySummary`

Phase 1 should wrap these, not replace them.

## 4. Workflow States

Use a small state vocabulary for workflow-level status:

| State | Meaning |
| --- | --- |
| `READY` | Workflow completed enough analysis to present a review report. |
| `NEEDS_INPUT` | Required candidate, owned item, or context is missing. |
| `REVIEW_REQUIRED` | Workflow found warnings, conflicts, low confidence, duplicates, or manual checks. |
| `BLOCKED` | An internal engine failed or required data was unavailable in a way that prevents useful output. |
| `COMPLETE` | Workflow has no immediate review actions. This remains advisory and does not imply mutation. |

Mapping from existing outputs:

- Existing `WorkflowSummary.status == "Review Ready"` maps to `READY`.
- Existing warning statuses map to `REVIEW_REQUIRED`.
- Missing required candidate for acquisition or upgrade maps to `NEEDS_INPUT`.
- Exceptions caught from source engines map to `BLOCKED` with warning/evidence details.
- Empty daily inbox with no warnings maps to `COMPLETE`.

Do not reuse `BUY_NOW`, `WATCH`, `PASS`, or other `AdvisorCategory` values as workflow states. Recommendation categories remain frozen.

## 5. Ownership Boundaries

### `collector_workflows.py`

Owns the Phase 1 unified workflow facade and normalized workflow DTOs.

Allowed changes:

- Add `WorkflowType`, `WorkflowState`, `WorkflowSeverity`
- Add `WorkflowRequest`, `WorkflowEvidence`, `WorkflowAction`, `UnifiedWorkflowReport`
- Add `CollectorWorkflowEngine.run_workflow()`
- Add private route helpers such as `_run_acquisition_review()`
- Add normalization helpers that convert existing reports into `UnifiedWorkflowReport`

### Existing engines

Remain owners of business logic:

- `AcquisitionWorkflow` owns acquisition orchestration already present in `collector_workflows.py`.
- `CollectionReviewWorkflow` owns dashboard/quality/integrity/snapshot review already present in `collector_workflows.py`.
- `UpgradeAdvisor` owns upgrade comparison logic.
- `CollectionIntelligenceEngine` owns duplicate, gap, and collection-priority analysis.
- `CollectorAdvisor` owns advisor recommendation categories and deterministic recommendation ordering.
- `CollectorWorkspace` owns panel aggregation.

### Not owned by Phase 1

Phase 1 does not own:

- GUI menus, tabs, dialogs, or home screen changes
- Persistence schema
- Recommendation memory
- New recommendation categories
- Collection mutation
- OCR/image recognition upgrades
- External data ingestion

## 6. Reuse Map

| Workflow | Primary reuse | Supporting reuse | Output source reports |
| --- | --- | --- | --- |
| Acquisition Review | `AcquisitionWorkflow.run()` | `PhotoAssistedEntry`, `OCRExperiment`, `OCRValidationEngine`, `SmartShoppingAssistant`, `ShoppingExplanationEngine` | `AcquisitionWorkflowReport` |
| Collection Review | `CollectionReviewWorkflow.run()` | `CollectionDashboard`, `CollectionQualityEngine`, `CollectionIntegrityAudit`, `CollectionSnapshotManager` | `CollectionReviewReport` |
| Upgrade Review | `UpgradeAdvisor` | `CollectionIntelligenceEngine`, optional `CollectorAdvisor` evidence | Upgrade report/result object from existing advisor |
| Duplicate Review | `CollectionIntelligenceEngine` | `CollectionIntegrityAudit`, collection dashboard duplicate data where available | Duplicate findings from existing intelligence/integrity reports |
| Daily Inbox | `CollectorWorkflowEngine.daily_summary()` | OCR reports, photo records, shopping candidates, collection review, photo review, workspace inbox when later integrated | `CollectorDailySummary` |

Implementation should prefer existing public methods over direct inspection of private fields.

## 7. Data Flow

### Engine Construction

```text
collection_items, want_list_intents, photo_records,
photo_candidates, shopping_candidates, ocr_reports,
market_awareness_engine, snapshot_manager
        |
        v
CollectorWorkflowEngine(...)
```

### Workflow Request

```text
WorkflowRequest(workflow_type, candidate, owned_item, raw_ocr_text, context)
        |
        v
CollectorWorkflowEngine.run_workflow(request)
        |
        v
route by WorkflowType
```

### Source Report

```text
existing workflow/engine report
        |
        v
normalization helper
        |
        v
UnifiedWorkflowReport
```

### Normalization

Each route should:

1. Call the existing engine/workflow.
2. Pull statuses, warnings, recommended actions, and headline text.
3. Convert statuses to `WorkflowEvidence`.
4. Convert next actions to `WorkflowAction`.
5. Preserve the original report in `source_reports`.
6. Assign a deterministic `WorkflowState`.

No route should save, mutate, delete, import, buy, sell, grade, submit, scrape, or call an external API.

## 8. Error Handling

Phase 1 should degrade gracefully.

Rules:

1. Missing `WorkflowRequest` or invalid `workflow_type` raises `ValueError`.
2. Missing acquisition candidate returns `UnifiedWorkflowReport(state=NEEDS_INPUT)`.
3. Missing upgrade candidate or owned item returns `UnifiedWorkflowReport(state=NEEDS_INPUT)`.
4. Empty collection data is allowed and should return a report with evidence explaining limited analysis.
5. Source engine exceptions are caught inside the route and converted into `BLOCKED` reports unless the error is a programmer error in request construction.
6. Warnings should be plain strings in `warnings` and source-labeled items in `evidence`.
7. Deterministic ordering should be applied to evidence and actions, using source name then detail when no stronger local order exists.
8. The report should never contain partially mutated collection state because Phase 1 performs no mutations.

Recommended blocked report helper:

```python
def _blocked_report(workflow_type: WorkflowType, title: str, error: Exception) -> UnifiedWorkflowReport:
    return UnifiedWorkflowReport(
        workflow_type=workflow_type,
        state=WorkflowState.BLOCKED,
        title=title,
        summary="Workflow could not complete because a source engine failed.",
        evidence=[WorkflowEvidence(source="collector_workflows", detail=str(error), severity=WorkflowSeverity.ERROR)],
        warnings=[str(error)],
    )
```

## 9. Test Plan

Add or extend `test_collector_workflows.py`.

### API Tests

- `WorkflowType` exposes exactly five values.
- `WorkflowState` exposes the approved state vocabulary.
- `WorkflowRequest` normalizes required fields.
- `UnifiedWorkflowReport` defaults lists/dicts safely.
- `run_workflow()` rejects invalid workflow types.

### Workflow Route Tests

- Acquisition Review with candidate returns `UnifiedWorkflowReport`.
- Acquisition Review without candidate returns `NEEDS_INPUT`.
- Collection Review returns dashboard/quality/integrity evidence.
- Upgrade Review returns review output using existing upgrade logic.
- Upgrade Review missing candidate or owned item returns `NEEDS_INPUT`.
- Duplicate Review returns duplicate/lower-grade duplicate evidence when duplicates exist.
- Daily Inbox returns OCR/photo/shopping/integrity tasks from existing summary logic.

### Guardrail Tests

- No workflow mutates `collection_items`.
- No workflow writes files.
- No workflow requires GUI imports.
- No workflow adds or changes `AdvisorCategory`.
- `run_workflow()` is deterministic for identical input.
- Empty inputs produce useful reports rather than crashes.
- Source engine failure produces `BLOCKED` with evidence and warning text.

### Regression

- Existing `test_collector_workflows.py` tests continue to pass.
- Full `python -m unittest discover` passes.
- If the local `py` launcher remains unavailable, note that `python -m unittest discover` is the verified local command.
