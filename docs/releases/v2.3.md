# Coin Analyzer v2.3

Release date: 2026-06-18

Release hash: See verified tag `v2.3`

## Overview

Coin Analyzer v2.3 adds Mobile Readiness. This release does not build a mobile app, web app, API, OCR workflow, scraping workflow, live market pricing, or Numista integration. It creates a deterministic audit layer that documents where the Collector Operating System is already service-oriented and where desktop assumptions must be abstracted before future mobile work.

## Major Features

- `MobileReadinessAuditor` for repeatable mobile-readiness reporting.
- `MobileReadinessReport` with desktop dependency findings, service boundary findings, mobile input findings, API-readiness mappings, phone workflow steps, and a readiness score.
- `MobileReadinessScore` with architecture, workflow, persistence, exports, and inputs categories.
- Documentation-only API mapping for future endpoints:
  - `analyze_candidate`
  - `collection_health`
  - `shopping_recommendations`
  - `dashboard_summary`
- Coin-show phone workflow audit for reaching a BUY/PASS decision from a candidate coin and asking price.
- CSV and Markdown export for readiness reports.

## Desktop Dependency Findings

- Tkinter remains the primary desktop UI and is a mobile blocker.
- Desktop file dialogs are used for workbook, export, backup, and photo workflows.
- Workbook loading is reusable but still path-based.
- CSV/Markdown exports are portable but local destination handling must be abstracted.
- Photo Vault currently stores local paths rather than mobile photo URIs.
- JSON persistence is portable in format, but storage paths are desktop/project-root based.

## Service Boundary Findings

- Collection Intelligence, Listing Analyzer, Smart Shopping Assistant, and Acquisition Workflow are strong candidates for future mobile service calls.
- Collection Dashboard and Collection Health Report already return structured data but still expose local export destinations.
- Persistence Layer and Backup Manager are reusable in concept, but mobile work needs storage-provider and file-destination adapters.

## Mobile Readiness Score

- Overall score: 68
- Architecture: 72

The score is intentionally conservative. The project has a strong deterministic service foundation, but desktop UI, local file dialogs, local photo paths, and project-root storage remain blockers for mobile use.

## Phone Workflow Audit

Current dealer-table workflow:

1. Open the app and restore or load collection context.
2. Open Listing Analyzer or Do I Own This.
3. Enter country, denomination, year, grade, and asking price.
4. Run candidate/acquisition analysis.
5. Review ownership, duplicate, upgrade, WANT_LIST, and impact status.
6. Decide BUY, PASS, WATCH, NEGOTIATE, or REVIEW.

Recommended future improvements:

- Add app-scoped mobile state restoration.
- Add a compact dealer-table candidate-entry workflow.
- Place recommendation and max rational price first, then show expandable reasoning.
- Use storage and photo URI adapters before attempting a mobile interface.

## Known Limitations

- No mobile app, web app, API server, OCR, image recognition, scraping, live pricing, market prediction, Numista expansion, user accounts, cloud sync, or database server.
- Mobile endpoint mappings are documentation only.
- Readiness findings are deterministic architectural findings, not automated static analysis.
- Future mobile work should first introduce storage, file picker, and photo URI abstractions.
