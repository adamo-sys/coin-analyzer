# v8.4 Release Notes — Connected Data

## Release Summary

🔗 Connected Data — make information entered once available everywhere it is relevant.

📷 Photos automatically available for grading, entry, and batch workflows.

🤖 AI Grading consumes existing OCR and collection context without extra user input.

🛒 Smart Shopping references Want Lists, Collection Intelligence, and AI assessments together.

📊 Collector Workspace shows cross-referenced views of connected information.

🔄 Session Context auto-propagates to all relevant engines without manual loading.

⚠️ Thin orchestration — no new intelligence engine, no new persistence layer, no duplicated business logic.

---

## Overview

Connected Data is the cross-referencing and auto-propagation layer that makes the collector's existing information flow between tools without manual re-entry.

v8.3 unified the workspace — the collector opens one window and sees all panels. v8.4 connects the panels — information entered in one tool automatically appears where it is relevant in others.

### Example: The Photo Lifecycle (Before vs After)

**Before v8.4:**
```
Capture Photo → Photo Vault (manual review)
              → OCR Experiment (manual entry)
              → AI Grading (manual re-entry of country/denom/year)
              → Batch Processing (manual re-entry)
              → Collection Entry (manual re-entry)
```

**After v8.4:**
```
Capture Photo → Photo Vault (auto-linked)
              → OCR (auto-linked to photo)
              → AI Grading (auto-populated from OCR + collection context)
              → Batch Processing (auto-includes grading assessment)
              → Collection Entry (auto-populated from OCR + grading + intelligence)
```

### Example: The Shopping Lifecycle (Before vs After)

**Before v8.4:**
```
Deal Hunter → Shopping Assistant (manual candidate entry)
            → Market Intelligence (manual comparable entry)
            → Acquisition Workflow (manual re-entry)
            → Watchlist (manual watch creation)
```

**After v8.4:**
```
Deal Hunter → Shopping Assistant (auto-enriched with intelligence context)
            → Market Intelligence (auto-pulls historical observed prices)
            → Acquisition Workflow (auto-includes market context + intelligence)
            → Watchlist (auto-detects matches)
```

## Mission

**"One piece of information entered once, reused everywhere."**

The collector takes a photo once. The OCR runs once. The collection intelligence is computed once. Every tool that needs that information should receive it automatically, without the collector re-entering the same country, denomination, year, grade, or photo reference.

---

## Design Principle

**Connection, not duplication.**

Connected Data does not create new data models, new storage, or new intelligence. It creates cross-references between existing data so that:

1. **Auto-propagation**: Session context, photo metadata, OCR results, and grading assessments flow to relevant engines automatically.
2. **Cross-referencing**: Workspace panels show how data from different engines relates to each other.
3. **Auto-population**: Tool dialogs pre-fill fields from related data the collector has already entered.
4. **Connected exports**: Reports include cross-referenced context from multiple engines.

```
Photo Vault ──┬──→ AI Grading (photo refs auto-linked)
              ├──→ Batch Processing (photo metadata auto-included)
              ├──→ Collection Assistant (photo coverage auto-shown)
              └──→ Workspace Photo Vault panel (coverage metrics)

OCR Results ────┬──→ AI Grading (candidate auto-populated)
                ├──→ OCR Validation (auto-validated)
                ├──→ Identification (auto-candidate)
                └──→ Collection Entry (auto-proposed fields)

Collection Intelligence ──┬──→ Smart Shopping (gaps/upgrades auto-targeted)
                          ├──→ Deal Hunter (collection context auto-scored)
                          ├──→ AI Grading (pattern analysis auto-included)
                          └──→ Workspace Want List (auto-updated)

Market Awareness ────┬──→ Market Intelligence (historical prices auto-referenced)
                     ├──→ Acquisition Workflow (observed price context)
                     └──→ Portfolio Performance (acquisition history)

Session Context ────┬──→ All engines (workbook/WANT_LIST auto-propagated)
                    └──→ Workspace (all panels auto-enriched)
```

## Permanent Architectural Rules

1. **CollectorWorkspace remains a ViewModel only.** Connection methods cross-reference existing panel outputs; they do not compute new business logic.
2. **No new intelligence engine.** All analysis, scoring, and recommendations remain in existing engines.
3. **No new persistence layer.** Connected data holds references, not copies. Source engines remain the owners.
4. **No duplicated business logic.** If an engine already computes it, the connection layer references it.
5. **Keyword-only context propagation.** All new context parameters are keyword-only, preserving existing API signatures.
6. **Lazy connection.** Cross-references are computed on demand, not eagerly.
7. **Graceful degradation.** If related data is missing, the tool works normally without it.

## New Module: `connected_data.py`

A thin facade that cross-references existing engine outputs. No new business logic. No new data models.

```python
@dataclass
class ConnectedContext:
    """Shared references to all active data sources. No copies. No persistence."""
    collection_items: List[Any]
    photo_records: Optional[List[Any]] = None
    ocr_reports: Optional[List[Any]] = None
    grading_assessments: Optional[List[Any]] = None
    market_records: Optional[List[Any]] = None
    shopping_candidates: Optional[List[Any]] = None
    want_list_intents: Optional[List[Any]] = None
    watchlists: Optional[List[Any]] = None
    workflow_statuses: Optional[List[Any]] = None
    session_context: Optional[Any] = None
    photo_candidates: Optional[List[Any]] = None
    acknowledged_action_ids: Optional[List[str]] = None

class ConnectedDataEngine:
    """Cross-reference existing engine outputs. No new intelligence."""

    def __init__(self, context: ConnectedContext):
        self.context = context

    def link_photos_to_grading(self) -> List[Dict]:
        """Match photo records to grading assessments by photo reference."""

    def link_ocr_to_grading(self) -> List[Dict]:
        """Match OCR candidates to grading assessments by country/denom/year."""

    def link_intelligence_to_shopping(self) -> List[Dict]:
        """Match collection intelligence targets to shopping candidates."""

    def link_market_to_acquisition(self, country, denomination, year) -> List[Dict]:
        """Match historical market records to acquisition candidates."""

    def link_watchlist_to_deals(self, deals: List[Any]) -> List[Dict]:
        """Match watchlist entries to deal candidates."""

    def link_batch_to_grading(self, batch_candidates: List[Any]) -> List[Dict]:
        """Match batch candidates to grading assessments."""

    def generate_cross_reference_report(self) -> Dict:
        """Summary of all cross-references between data types."""
```

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Circular dependencies between engines | Low | High | Engines only accept optional context params; no engine imports another engine |
| Performance degradation from cross-referencing | Medium | Low | All cross-referencing is lazy; cache in workspace; no eager computation |
| Breaking existing engine behavior | Medium | High | All new params are keyword-only with None defaults; existing tests unchanged |
| Scope creep (adding new intelligence) | Medium | High | Strict "connection only" rule; no new scoring logic; architecture review gate |
| GUI complexity increase | Medium | Medium | New tabs are optional; "Open in Tool..." pattern preserved; auto-population is opt-in |
| Session context stale data | Low | Medium | `refresh()` clears connected cache; engines re-query source on each call |

## Guardrails

- **No new intelligence engine.** `ConnectedDataEngine` is a cross-referencing facade only. It does not score, rank, or recommend.
- **No new persistence layer.** `ConnectedContext` holds references. No JSON files, no database, no new storage format.
- **No duplicated business logic.** Cross-referencing is matching by ID, country/denomination/year, or photo reference. No re-computation of scores, grades, or recommendations.
- **Read-only connections.** The connection layer never modifies collection data, engine outputs, or persisted state.
- **Keyword-only all new params.** Existing engine signatures remain unchanged for all positional callers.
- **Graceful degradation.** If related data is missing, the tool works normally. No hard dependencies on connected data.
- **No ML.** No machine learning, no neural networks, no probabilistic matching. Cross-referencing is deterministic (exact match, fuzzy string match, or ID lookup).
- **No computer vision.** No image recognition, no automated grading from pixels. Photos are metadata-only references.
