# v8.1 Release Notes — Batch Processing

## Overview

Batch Processing extends the Smart Phone Cataloguer to handle an entire folder of photos in a single operation. It provides deterministic, offline batch intake, validation, analysis, and reporting without introducing new OCR, matching, or cataloguing logic.

## Mission

Process an entire folder of photos through the existing Smart Phone Cataloguer pipeline.

## Pipeline

```
Folder
   │
   ▼
PhotoCaptureWorkflow
   │
   ▼
SmartPhoneCataloguer
   │
   ▼
OCR Identification
   │
   ▼
Collection Matching
   │
   ▼
Proposed Collection Entries
   │
   ▼
Batch Review Report
```

## Features

### Phase 1: Batch Photo Intake
- Select a folder of photos in one operation
- Auto-pair front/back images by filename pattern
- Create batch capture sessions

### Phase 2: Batch OCR & Identification
- Reuse existing OCR Identification Engine
- Process all images, collect per-image confidence and review flags
- Handle per-image failures without aborting the batch

### Phase 3: Batch Collection Intelligence
- Reuse existing Collection Intelligence Engine
- Run duplicate/upgrade/gap analysis on all candidates in one pass
- Consolidated duplicate warnings and upgrade opportunities

### Phase 4: Batch Reporting & Export
- One consolidated batch report with per-item details and summary statistics
- CSV export with all candidate fields, scores, and recommendations
- Markdown export with batch summary, top opportunities, and warnings

### Phase 5: GUI Integration
- Tools → Batch Processing menu item
- Folder selection dialog
- Progress indicators for long batch operations
- Results review dialog with per-item expandable details

## Architecture
- Reuses v8.0 Photo Capture Engine (`photo_capture.py`)
- Reuses v8.0 OCR Identification Engine (`ocr_identification.py`)
- Reuses v8.0 Collection Intelligence Engine (`collection_intelligence.py`)
- Reuses v8.0 Smart Phone Cataloguer (`smart_phone_cataloguer.py`)
- New: `batch_processing.py` — batch orchestration engine (thin, API-first)
- New: `test_batch_processing.py` — comprehensive tests
- Modified: `coin_collection_gui.py` — Tools menu integration

## Design Principle

Favor reuse over invention. `batch_processing.py` is an orchestration layer only. No new OCR, no new matching, no new cataloguing logic. The public API is designed first; implementation stays thin.
