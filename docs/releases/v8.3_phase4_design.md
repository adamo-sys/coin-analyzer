# v8.3 Phase 4 Design — Refresh & Lifecycle Hardening

## Status

DESIGN ONLY — awaiting approval before implementation.

## Scope

**Phase 4 is deliberately small.** It hardens the lifecycle guarantees established in Phases 1–3. No new panels, no new capabilities, no GUI. Just tests and minor API surface to verify and expose lifecycle state.

### In Scope
- `LifecycleInfo` dataclass — diagnostic snapshot of workspace state
- `get_lifecycle()` method — returns engine count, cache state, panel access counts
- `refresh()` hardening — verify cache-only invalidation, engine preservation
- Cache behavior verification — stale data, per-instance isolation, key collision
- Error handling edge cases — double failure, cascading errors, partial recovery
- Unit + integration tests (6–10 new tests)

### Out of Scope (confirmed)
- No new panels
- No new report types
- No GUI
- No persistence
- No business logic
- No engine recreation on refresh

## Lifecycle Rules (Permanent)

```
refresh()
    ↓
self._cache.clear()     ← ONLY this
    ↓
engines stay alive      ← NEVER recreate
    ↓
next panel access
    ↓
lazy re-query engine
```

**Invariant:** `refresh()` never touches `self._engines`. It only clears `self._cache`.

**Consequence:** Engines are created at most once per workspace instance. They live for the instance lifetime.

**Consequence:** If collection data mutates externally, `refresh()` + next panel access will see the new data because engines re-query on demand.

### Cache guarantees

1. **Per-instance isolation** — Each `CollectorWorkspace` instance has its own cache. No cross-instance pollution.
2. **No stale data within a panel** — After `refresh()`, the next call to a panel getter re-queries the engine.
3. **No key collision** — Each panel has a unique cache key. No overlap between panels.
4. **Reports menu is cached** — `get_reports()` returns cached metadata after the first call.

## Error Handling Edge Cases

### Double failure
Same engine fails on first call and on re-query after refresh. Panel should return error both times, not crash.

### Cascading errors
Panel A fails, Panel B succeeds, Panel C fails. All three should return partial data with their own error lists. No cross-panel pollution.

### Partial recovery
Engine fails on first call. After refresh, engine succeeds. Panel should return data on second call.

### Engine failure during export
`generate_report()` catches engine failure and returns structured error dict. `export_report()` raises on failure.

## Implementation Details

### `get_lifecycle()`

```python
def get_lifecycle(self) -> LifecycleInfo:
    """Return a diagnostic snapshot of workspace state. No engine calls."""
    return LifecycleInfo(
        engine_count=len(self._engines),
        cached_panel_count=len(self._cache),
        reports_menu_cached="reports" in self._cache,
        panel_names_cached=list(self._cache.keys()),
        collection_item_count=len(self._collection_items),
    )
```

Zero engine calls. Zero business logic. Pure state inspection.

### `refresh()` (already correct, no change needed)

```python
def refresh(self) -> None:
    """Clear all caches. Next panel query will re-query engines."""
    self._cache.clear()
```

No change from Phase 1. The hardening comes from tests, not code.
