## Overview

v1.1.0 is the first public minor release after the July 17, 2026 `v1.0.0` release.

The release packages the additive, backward-compatible product state reached after the capture-package, OCR review, privacy-boundary, regression, CI, and repository-governance hardening completed during the v1.1.0 release cycle.

The release is published and the annotated `v1.1.0` tag has been verified remotely.

## Major changes since public v1.0.0

- Hardened capture-package import with validated preparation, durable persistence, rollback/recovery, and explicit failure boundaries.
- Deterministic image-processing stages integrated into the desktop import path while preserving preview-before-confirmation behavior.
- Expanded OCR review workflow with explicit headless contracts, review-session persistence boundaries, and guarded desktop integration.
- Stronger architecture/privacy boundary checks around OCR/evaluation and legacy recognition paths.
- Broader cross-platform regression coverage and an incremental blocking Pyright boundary.
- Required Gitleaks and Ruff gates plus protected-branch workflow and explicit human merge/release authority.
- Optional OpenAI dependency smoke coverage without making cloud AI a core-runtime requirement.

## Current boundaries / known limitations

- Windows remains the primary supported desktop platform and native Tcl/Tk behavior still warrants manual smoke validation for GUI-sensitive changes.
- Collection storage remains local single-user JSON; users remain responsible for independent backups.
- Optional AI/live-provider behavior requires user-supplied credentials and network access; core collection management does not.
- OCR, image recognition, grading, and related visual inference remain advisory and require collector review.
- Benchmark/evaluation claims remain constrained by the repository's provenance, authorization, and human-review gates.
- Whole-repository Pyright remains advisory because existing type debt is being reduced incrementally rather than converted into a surprise blocker.

## Explicitly deferred from v1.1.0

The following quality-ratchet items were intentionally not release blockers:

- whole-repository type cleanup;
- broader Ruff rule adoption;
- additional property/mutation-test pilots;
- dependency-scanning experiments;
- CI optimization and auto-merge configuration;
- broad architecture refactors;
- benchmark work blocked by provenance, authorization, or evidence requirements.

Post-release work may advance these items independently without changing the v1.1.0 release record.
