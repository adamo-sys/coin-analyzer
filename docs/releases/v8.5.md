# v8.5 Release Notes — Collector Advisor

## Release Summary

🎯 **Collector Advisor** — deterministic, explainable recommendations that answer "What should I do next?"

📋 Every recommendation backed by evidence from existing engines.

🧩 Thin orchestration layer — no new intelligence, no duplicated logic.

💬 Every suggestion includes reasons the collector can read and verify.

⚠️ Advisory only — the collector decides, the software explains.

---

## Overview

Earlier releases built **capabilities**:

- v8.2: AI Grading Assistant — assess candidate quality
- v8.3: Collector Workspace — see everything in one place
- v8.4: Connected Data — information flows between tools

v8.5 builds **judgment** on top of those capabilities:

> **What should I do next?**

Not as a black-box prediction. Not as an LLM hallucination. As a deterministic, explainable recommendation built entirely from the engines already running in the workspace.

---

## Mission

**"Collector Advisor helps the collector decide what to do next using deterministic, explainable recommendations built entirely from existing engines."**

---

## Design Principle

**Orchestrate, don't absorb.**

The Advisor consumes outputs from existing engines — Collection Intelligence, Connected Data, Smart Shopping, AI Grading, Portfolio Performance, Photo Vault — and produces advisory recommendations. It does not reimplement their logic.

```
Collection Intelligence ──┐
Connected Data ─────────────┤
Smart Shopping ─────────────┤
AI Grading ─────────────────┼──→ CollectorAdvisor ──→ Advisory Report
Portfolio Performance ──────┤
Photo Vault ────────────────┤
Market Awareness ─────────────┘
```

---

## Permanent Architectural Rules

1. **CollectorAdvisor is a recommendation layer, not an intelligence engine.** All analysis stays in existing engines. The Advisor only orchestrates and explains.
2. **Every recommendation must be explainable.** Every recommendation DTO includes `evidence: List[str]` with human-readable reasons.
3. **CollectorAdvisor must be deterministic.** Given identical inputs and configuration, it must always produce identical recommendation ordering and evidence. This protects against subtle regressions and makes testing deterministic.
4. **No new intelligence engine.** No ML, no LLM, no black box, no probabilistic scoring. Deterministic logic only.
5. **No new persistence layer.** The Advisor reads from existing engines. No new JSON files, no database, no new storage format.
6. **No duplicated business logic.** If an engine already computes it, the Advisor references it.
7. **Keyword-only context parameters.** All new API parameters are keyword-only, preserving existing signatures.
8. **Graceful degradation.** If an engine is missing or fails, the Advisor degrades gracefully and reports what it could not evaluate.
9. **Public APIs are stable after Phase 1.** Breaking changes after Phase 1 require explicit documentation and justification.
10. **Advisory only.** The Advisor never modifies collection data, never makes purchases, never runs background jobs.
11. **Deterministic, testable, explainable.** Every recommendation must be reproducible from the same input data.

## New Module: `collector_advisor.py`

A thin orchestration layer that consumes existing engine outputs and produces advisory recommendations.

```python
@dataclass
class RecommendationReason:
    """Human-readable reason for a recommendation."""
    category: str           # e.g., "priority", "upgrade", "risk", "budget"
    description: str        # e.g., "highest priority want-list gap"
    source_engine: str      # e.g., "collection_intelligence", "smart_shopping"
    confidence: str        # "HIGH", "MEDIUM", "LOW"

@dataclass
class CollectorRecommendation:
    """A single advisory recommendation with evidence."""
    recommendation_id: str
    recommendation_type: str  # e.g., "PRIORITY_ACQUISITION", "GRADE_SUBMIT", "UPGRADE", "DISPOSE_DUPLICATE", "BUDGET_ALLOCATE", "NEXT_ACTION"
    title: str
    description: str
    evidence: List[RecommendationReason]
    priority_score: int       # 0-100, deterministic
    urgency: str               # "IMMEDIATE", "SHORT_TERM", "LONG_TERM", "ONGOING"
    status: str                # "ACTIVE", "COMPLETED", "DISMISSED", "REVIEW"
    related_items: List[str]   # IDs, paths, or references to related collection data

@dataclass
class AdvisorReport:
    """Complete advisory report with all recommendations."""
    recommendations: List[CollectorRecommendation]
    summary: str
    next_best_action: Optional[CollectorRecommendation]
    risks: List[str]
    opportunities: List[str]
    generated_at: datetime

class CollectorAdvisor:
    """Deterministic recommendation orchestrator."""

    def __init__(self, workspace: CollectorWorkspace):
        self.workspace = workspace

    def generate_advisory_report(self) -> AdvisorReport:
        """Generate complete advisory report from all engines."""

    def recommend_priority_acquisitions(self) -> List[CollectorRecommendation]:
        """Recommend highest-priority acquisitions from want-list, gaps, and opportunities."""

    def recommend_grade_submissions(self) -> List[CollectorRecommendation]:
        """Recommend candidates for grading submission based on AI Grading assessments."""

    def recommend_upgrades(self) -> List[CollectorRecommendation]:
        """Recommend upgrade candidates from collection intelligence and upgrade advisor."""

    def recommend_duplicate_disposal(self) -> List[CollectorRecommendation]:
        """Recommend duplicate candidates for sale/trade/disposal."""

    def recommend_budget_allocation(self) -> List[CollectorRecommendation]:
        """Recommend budget allocation across priority categories."""

    def recommend_next_action(self) -> Optional[CollectorRecommendation]:
        """Single "next best action" recommendation."""
```

## Recommendation Types

| Type | Description | Sources |
|------|-------------|---------|
| `PRIORITY_ACQUISITION` | Highest-priority items to acquire next | Want List, Collection Gaps, Smart Shopping, Opportunity Engine |
| `GRADE_SUBMIT` | Candidates ready for professional grading | AI Grading Assistant, Photo Vault |
| `UPGRADE` | Existing items with upgrade potential | Upgrade Advisor, Collection Intelligence |
| `DISPOSE_DUPLICATE` | Duplicates or surplus items to sell/trade | Collection Intelligence, Duplicate Detection |
| `BUDGET_ALLOCATE` | Suggested budget splits across categories | Acquisition Strategy, Portfolio Performance |
| `NEXT_ACTION` | Single best next step for the collector | All engines, ranked by priority and urgency |

## Explainability Requirement

Every recommendation must include evidence:

```
Recommendation: Upgrade 1910 Newfoundland 5¢

Evidence:
• [Collection Intelligence] Highest priority want-list gap
• [AI Grading] Existing example grades VG8
• [Smart Shopping] Estimated AU50 available within budget
• [Series Tracker] Completes Edward VII nickel set
• [Market Awareness] Recent comparable sales support value

Priority Score: 87/100
Urgency: SHORT_TERM
Confidence: HIGH
```

The user should never wonder: "Why did the software tell me to buy this?"

## Extension Points

### New Recommendation Types

1. Add new `recommend_*()` method to `CollectorAdvisor`.
2. Add new `RecommendationType` enum value.
3. Add evidence source in `RecommendationReason`.
4. Update `AdvisorReport` if new sections are needed.

### New Engine Sources

1. Identify engine that would benefit from recommendation exposure.
2. Add new `recommend_*()` method that consumes that engine's output.
3. Add `RecommendationReason` with appropriate `source_engine`.
4. Update workspace to pass the new engine context to the Advisor.

|------|-----------|--------|------------|
| Recommendation logic drifts into scoring/ranking | Medium | High | Strict "orchestrate only" rule; code review gate on every phase |
| Evidence generation becomes boilerplate | Medium | Medium | Require every `recommend_*()` method to include at least 2 evidence items in tests |

| Circular dependencies with existing engines | Low | High | Advisor only consumes workspace outputs; no engine imports Advisor |

## Guardrails

- **No new intelligence engine.** `CollectorAdvisor` is a recommendation orchestrator only. It does not score, rank, or recommend independently.
- **No new persistence layer.** `CollectorAdvisor` reads from existing engines. No JSON files, no database, no new storage format.
- **No duplicated business logic.** Cross-referencing and recommendation assembly only. No re-computation of scores, grades, or recommendations.
- **Read-only recommendations.** The Advisor never modifies collection data, engine outputs, or persisted state.
- **Every recommendation must be explainable.** Non-empty evidence list is mandatory. No opaque recommendations.
- **Deterministic ordering.** Given identical inputs and configuration, `CollectorAdvisor` must always produce identical recommendation ordering and evidence. This protects against subtle regressions and makes testing deterministic.
- **Keyword-only all new params.** Existing engine signatures remain unchanged for all positional callers.
- **Graceful degradation.** If an engine is missing or fails, the Advisor degrades gracefully and reports what it could not evaluate.
- **No ML.** No machine learning, no neural networks, no probabilistic matching. Recommendations are deterministic.
- **No LLM.** No large language model, no generative text, no black-box reasoning. Evidence is structured and traceable.
- **Advisory only.** The collector decides. The software explains.
