# v8.6 Release Notes - Unified Workflow

Release date: 2026-07-03

Status: Released

## Release Summary

v8.6 turns Coin Analyzer's existing collector intelligence into a unified workflow surface.

Where v8.4 made the application understand relationships through Connected Data, and v8.5 made it understand priorities through Collector Advisor, v8.6 makes it understand process. The release adds a deterministic workflow engine, exposes it through `CollectorWorkspace`, explains workflow state and evidence, displays the result in the existing Workspace Workflow tab, and polishes the Workflow Review markdown export.

## What Shipped

- Unified workflow DTOs: `WorkflowRequest`, `WorkflowEvidence`, `WorkflowAction`, and `UnifiedWorkflowReport`.
- Workflow states: `READY`, `NEEDS_INPUT`, `REVIEW_REQUIRED`, `BLOCKED`, and `COMPLETE`.
- Workflow routes for Acquisition Review, Collection Review, Upgrade Review, Duplicate Review, and Daily Inbox.
- `CollectorWorkflowEngine.run_workflow(request)` as a single deterministic workflow entry point.
- `CollectorWorkspace.get_workflows()` for the default Daily Inbox view.
- `CollectorWorkspace.get_workflow(request)` for explicit workflow execution.
- Workflow cache namespace compatible with `refresh()`.
- Workflow Review report descriptor under the `Workflow` category.
- Markdown-only Workflow Review export.
- Explainability metadata: `state_reason`, `recommended_tool`, and `recommended_tool_label`.
- `RecommendedTool` enum for stable metadata instead of scattered free-form tool strings.
- Existing Collector Workspace Workflow tab enhanced to display unified workflow output.
- Metadata-driven "Open..." buttons that call only existing GUI methods.
- Release-quality Workflow Review markdown structure with stable empty states.

## Architecture

v8.6 preserves the project's established layering:

```text
Existing engines and DTOs
        |
        v
CollectorWorkflowEngine
        |
        v
CollectorWorkspace
        |
        v
Collector Workspace GUI and Reports Panel
```

The GUI consumes `CollectorWorkspace` only. It does not call `CollectorWorkflowEngine` directly.

## Safety Boundaries

v8.6 remains:

- local-first
- deterministic
- review-only
- source-labeled
- non-mutating unless the collector uses an existing explicit collection action

v8.6 does not add:

- new workflow types beyond the five approved routes
- new recommendation categories
- new persistence
- collection mutation
- ML/CV behavior
- external APIs
- scraping
- background jobs
- automatic buying, selling, grading, deletion, or conflict resolution
