# v7.4 Collection Assistant

## Summary

Collection Assistant orchestrates existing Photo Capture, OCR Identification, Collection Intelligence, Collection Insights, and Acquisition Strategy engines into a single guided review experience for dramatically reducing manual cataloguing work while preserving user review and approval for every collection change.

This is deterministic, explainable, and derived only from local collection data. No AI reasoning, forecasting, machine learning, or external APIs.

## What's New

- `CollectionAssistantEngine` - main orchestrator for collection assistant workflows
- `CollectionAssistantSession` (via `AssistantSummary`) - manages a collection assistant session with start/end tracking, duration metrics, and completion status
- `CollectionAssistantCandidate` - a candidate item with photo info, OCR results, collection match, gap analysis, acquisition priority, and review status
- `AssistantReviewQueue` - queue of candidates for review with filtering, sorting, progress tracking, and completion detection
- `PhotoInfo` - photo metadata with side detection (obverse/reverse), quality assessment, auto-pairing, and orientation tracking
- `OCRCandidate` - OCR extraction result with year/denomination/country/variety detection, confidence scoring, trust levels, and evidence
- `CollectionMatch` - collection lookup result with exact/similar matching, duplicate risk assessment, and upgrade opportunity detection
- `CollectionGapInfo` - gap analysis for series/date/denomination/country coverage
- `AcquisitionPriorityInfo` - WANT_LIST and acquisition strategy priority matching
- `SideBySideComparison` - side-by-side review view with candidate, existing match, suggested identification, evidence, recommendations, and warnings
- `ProductivityMetrics` - measures photos processed, OCR success rate, review completion, approval rate, average confidence, and estimated time saved
- Photo workflow: drag-and-drop support via file dialog, multi-photo import, automatic obverse/reverse pairing from filenames, missing-side detection, photo quality assessment (file size based), orientation normalization
- OCR workflow: multiple OCR candidate processing, confidence scoring, evidence collection, review workflow, retry handling, deterministic text parsing for year/denomination/country/variety
- Cataloguing Assistant: guided review workflow for each candidate with detected coin, confidence, existing collection lookup, duplicate detection, gap detection, acquisition priority, and review status
- Side-by-Side Review: current candidate -> existing collection match -> suggested identification -> evidence -> Approve/Reject/Needs Review
- Batch Review: review queue with filtering, sorting, progress tracking, and incomplete review detection
- GUI integration: Tools -> Collection Assistant dialog with Review Queue, Current Candidate, and Productivity Metrics tabs
- Export support: Markdown and CSV for Assistant Session, Review Queue, and Productivity Report

## Architecture

The Collection Assistant Engine extends existing platform capabilities:

- Reuses Photo Vault infrastructure for photo metadata and linking
- Reuses OCR Identification engine for text extraction and validation
- Reuses Collection Intelligence for duplicate detection and collection lookup
- Reuses Collection Insights for gap analysis and observations
- Reuses Acquisition Strategy for priority matching and budget guidance
- Reuses Series Tracker for series completion and gap detection
- Reuses Collection Dashboard for collection context

The engine does not create new decision logic. It orchestrates and extends existing engines into a higher-level cataloguing workflow layer.

## Limitations

- Deterministic local guidance only. No scraping, APIs, live pricing, market forecasting, automatic purchasing, or collection mutation.
- OCR is simulated from text input in the current implementation. Full image-based OCR would require integration with the existing OCR engine.
- Photo quality assessment is file-size based, not pixel-level analysis.
- Auto-pairing relies on filename patterns, not image content analysis.
- Side detection from filenames uses keyword matching, not image recognition.
- Estimated time saved is a heuristic (90 seconds per item), not measured from actual user behavior.
- Collection matching uses simple string comparison, not fuzzy matching or semantic understanding.
- No automatic insertion into collection. User approval remains mandatory for every change.
