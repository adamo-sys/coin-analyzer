## Release Summary

v1.3.0 advances Coin Analyzer's local-first collection workflow with a bounded phone-intake path, a reproducible phone-photo recognition benchmark, operator-facing Command Center projections, and stronger repository-level controls for agent-assisted development.

The release consolidates the merged work after the public `v1.2.0` baseline through PR #245. RC preparation is scope-frozen: no new recognition tuning, feature expansion, or architecture experiments are included.

## Historical RC1 regression and acceptance evidence

Full regression suite:

- 5,732 passed
- 32 skipped
- 0 failures
- Runtime: 263.39 seconds

The working tree remained clean after the completed regression run.

Manual Windows/native phone-intake acceptance was also exercised with a transferred two-image iPhone JPEG pair. Import, explicit Front/Reverse assignment, same-physical-coin confirmation, READY persistence, native preview/layout, provider disclosure, review deferral, proposal rejection, and no-mutation-on-rejection behaved as designed. The same pair remained READY with its assigned roles after defer/reject cycles. Recognition quality itself was not accepted by this test: repeated provider runs produced materially incorrect and inconsistent identity proposals, which the collector-review boundary successfully prevented from modifying collection data. Corrected-identity persistence/save and post-save Work Queue verification were subsequently completed successfully: the operator corrected the proposal to Canada / 25 cents / 2023 / Caribou, confirmed and saved it, fully restarted the application, verified the saved record persisted, and confirmed the Work Queue reported zero unresolved identity, reverse-photo, or purchase-price tasks.

During that acceptance work, a stale parent-set recovery defect was reproduced: after previously imported photos were removed and the same deterministic files later returned, the individual photos recovered to READY while their parent photo set remained incorrectly in ERROR. Commit 2bd8679 (fix(photo-inbox): recover sets when missing photos return) adds bounded recovery for the missing-file error state. The regression test failed before the production fix and passed afterward; the full test_photo_inbox.py suite passed 17 tests. Native GUI verification then confirmed the previously stale set recovered to NEW with both photos READY, zero missing photos, and zero duplicates after restart.

Focused subsystem coverage added since `v1.2.0` includes phone intake, phone-photo benchmarking, standalone image intake, Command Center, and Foundation task-state controls.

Focused RC audit checks also passed for core collection export (2 tests), the explicit workspace no-business-logic architecture invariant (1 test), legacy image-path-only record loading (1 test), and the corrected identity confirm/save/reload boundary (1 test). These targeted checks supplement the completed full regression suite.
