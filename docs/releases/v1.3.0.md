# v1.3.0 Release Notes

Release candidate: `v1.3.0-rc1`

## Release Summary

v1.3.0 advances Coin Analyzer's local-first collection workflow with a bounded phone-intake path, a reproducible phone-photo recognition benchmark, operator-facing Command Center projections, and stronger repository-level controls for agent-assisted development.

The release consolidates the merged work after the public `v1.2.0` baseline through PR #245. RC preparation is scope-frozen: no new recognition tuning, feature expansion, or architecture experiments are included.

## Architecture and Boundaries

v1.3.0 preserves the project's local-first and evidence-oriented architecture.

The phone-photo benchmark remains a bounded evaluation path rather than an uncontrolled production recognition rewrite. Command Center remains an operator projection/orchestration surface rather than a second source of business logic. Foundation/preflight controls govern repository work without replacing application behavior.

Historical internal `v8.x` and `v9.x` milestone labels remain historical development identifiers. Current runtime provenance follows the public semantic-version line.

During RC preparation, unreleased runtime provenance remains:

`v1.2.0+dev`

The exact release-candidate identifier is not written into runtime provenance until the applicable release gates have passed.

## Tests

Full regression suite:

- 5,731 passed
- 32 skipped
- 0 failures
- Runtime: 766.97 seconds

The working tree remained clean after the completed regression run.

Manual Windows/native phone-intake acceptance was also exercised with a transferred two-image iPhone JPEG pair. Import, explicit Front/Reverse assignment, same-physical-coin confirmation, READY persistence, native preview/layout, provider disclosure, review deferral, proposal rejection, and no-mutation-on-rejection behaved as designed. The same pair remained READY with its assigned roles after defer/reject cycles. Recognition quality itself was not accepted by this test: repeated provider runs produced materially incorrect and inconsistent identity proposals, which the collector-review boundary successfully prevented from modifying collection data. Successful corrected-identity persistence/save and post-save Work Queue verification remain to be completed before the native collector-acceptance gate can be marked PASS.

Focused subsystem coverage added since `v1.2.0` includes phone intake, phone-photo benchmarking, standalone image intake, Command Center, and Foundation task-state controls.
