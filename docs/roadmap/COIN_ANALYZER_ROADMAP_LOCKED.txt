PHASE 1 — SPRINT 11: DESKTOP OCR REVIEW EXPERIENCE

Sprint 11A — Presentation models
- Create immutable UI-facing models for OCR candidates, decisions, conflicts,
  provenance, final projection status, and unresolved fields.
- No Tkinter logic in domain services.
- No persistence.
- No collection mutation.
- No direct binding to mutable legacy OCR models.

Sprint 11B — Review-session controller
- Coordinate OCR report -> human decisions -> Sprint 10 review session -> display state.
- Delegate all business rules to Sprint 10 services.

Sprint 11C — Opt-in desktop composition
- Add an explicit OCR review feature flag or factory.
- Default desktop workflow remains OCR-free.
- No hidden registration or auto-enablement.

Sprint 11D — Candidate-review UI
- Approve, correct, reject, defer.
- Next/previous candidate.
- Source-image preview.
- Provenance display.

Sprint 11E — Conflict-resolution UI
- Select existing value.
- Enter corrected value.
- Defer.
- Compare source provenance.

Sprint 11F — Desktop integration tests
- Exercise the real composition path, not only controller spies.

Sprint 11 exit gate
- OCR review works interactively.
- No collection data is changed.
- Closing the app may discard the review session.
- Default desktop behavior remains OCR-free.
- Full regression passes.

PHASE 4 — SPRINT 14: COLLECTION CHANGE PLANNING

Sprint 14A — Collection mapping design
Document:

- Unsupported mappings.
- Overwrite behavior.
- Blank-field behavior.
- Conflicting existing values.

Sprint 14B — Proposed-change contracts
Create immutable change-plan DTOs containing:
- Existing value.
- Proposed value.
- Source provenance.
- Change type.
- Reason.

Possible change types:
- Populate blank.
- Replace existing.
- No change.
- Unsupported.
- Conflict.

Sprint 14C — Dry-run planner
- Generate a collection change plan without mutation.

Sprint 14D — Change preview UI
Show:
- What will change.
- What will remain unchanged.

- Whether existing data will be overwritten.

Sprint 14E — Explicit approval command
- Require a second explicit approval after OCR review.
- Human review approval and collection-change approval remain separate acts.

Sprint 14 exit gate

- Nothing is written automatically.
- Every proposed change is auditable.
- Existing collection values are protected by policy.

PHASE 5 — SPRINT 15: CONTROLLED COLLECTION MUTATION

Sprint 15A — Mutation command
Accept only an approved change plan.
Reject:
- Incomplete plans.
- Unresolved conflicts.
- Unsupported fields.
- Grade.
- Stale collection state.
- Already-applied operations.

Sprint 15B — Atomic persistence
Safe-write flow:
validate -> write temporary file -> fsync where supported -> atomic replace -> verify

Sprint 15C — Rollback and backup
- Create a recoverable backup before mutation.

Sprint 15D — Audit record

- Schema version.

Sprint 15E — Desktop apply workflow

approve changes -> apply atomically

Sprint 15F — End-to-end tests

Sprint 15 exit gate

- Every write is previewed, approved, atomic, and auditable.

LOCKED ARCHITECTURAL RULES

1. OCR never writes directly to the collection.
2. Human review and collection-change approval are separate steps.
3. Grade remains excluded from OCR-derived updates.
4. Unresolved or deferred values never silently receive a winner.
5. Default desktop import remains OCR-free until explicitly enabled.
6. Persistence is versioned before review sessions are stored.
7. Collection writes are previewed, approved, atomic, and recoverable.
8. Domain rules remain outside GUI controllers.
9. No legacy mutable OCR model crosses into the hardened workflow domain.
10. Every sprint closes with focused tests, full regression, architecture review,
    documentation, and a clean working tree.
