# v8.6 Phase 4 Design - Workflow GUI Integration

Status: DESIGN ONLY. Awaiting approval before implementation.

## Mission

Make the unified v8.6 workflow visible and usable inside the existing Collector Workspace GUI.

Phase 4 should enhance the existing Workspace `Workflow` tab so it displays `UnifiedWorkflowReport` content from `CollectorWorkspace.get_workflows()`. The GUI remains a consumer of the workspace layer only.

## 1. GUI Placement

Use the existing Collector Workspace dialog in `coin_collection_gui.py`.

Current placement:

- `open_collector_workspace()`
- `_create_workspace_tabs()`
- `_create_workflow_tab()`
- `_refresh_workspace_tabs()`
- `_format_workflow_status()`

Recommended Phase 4 placement:

- Keep the existing `Workflow` tab.
- Change the tab data source from `workspace.get_workflow_status()` to `workspace.get_workflows()`.
- Add a new formatter such as `_format_unified_workflow(report)`.
- Keep `get_workflow_status()` untouched for backward compatibility unless another existing caller depends on the old status display.

No new top-level window is required.

## 2. Display Layout

The tab can remain a simple read-only text panel plus a small button row, matching the other Collector Workspace tabs.

Recommended text layout:

```text
Workflow Review
========================================

Workflow Type:      DAILY_INBOX
State:              REVIEW_REQUIRED
State Reason:       Daily Inbox found workflow items that require collector review.
Recommended Tool:   Workflow Review

Summary
----------------------------------------
Daily collector priorities generated

Next Actions
----------------------------------------
- Review OCR items
  Reason: Daily collector priorities generated
  State: REVIEW_REQUIRED
  Open: OCR Experiment

Evidence
----------------------------------------
- [WARNING] WorkflowStatus: OCR Pending: 1 OCR report(s) need review
  Action: Review OCR validation reports

Warnings
----------------------------------------
- OCR Pending: 1 OCR report(s) need review
```

Rules:

- Always show workflow type, state, `state_reason`, `recommended_tool`, and `recommended_tool_label`.
- Show action labels, reasons, states, action-level tool labels, and action evidence.
- Show report evidence with severity, source, detail, and evidence action.
- Keep content read-only.
- Keep wording plain and compact; this is a workspace panel, not a wizard.

## 3. Tool-Button Mapping

Use `RecommendedTool` metadata as display/navigation hints only. The GUI may map enum values to existing GUI methods, but must not add callbacks, routes, URLs, shell commands, or new launch concepts.

Allowed mapping:

| RecommendedTool | Button Label | Existing GUI Method |
| --- | --- | --- |
| `SMART_SHOPPING` | Open Smart Shopping | `open_smart_shopping_assistant` |
| `UPGRADE_ADVISOR` | Open Upgrade Advisor | `open_upgrade_advisor` |
| `DUPLICATE_REVIEW` | Open Collection Assistant | `open_collection_assistant` |
| `COLLECTION_DASHBOARD` | Open Collector Home | `open_collector_home` or `open_collector_home_dashboard` |
| `COLLECTION_INTEGRITY` | Open Collection Integrity | `open_collection_integrity_audit` |
| `PHOTO_VAULT` | Open Photo Vault Audit | `open_photo_vault_audit` |
| `OCR_EXPERIMENT` | Open OCR Experiment | `open_ocr_experiment` |
| `WANT_LIST` | Open Want List Generator | `open_want_list_generator` |
| `AI_GRADING` | Open AI Grading Assistant | `open_ai_grading_assistant` |
| `WORKFLOW` | Refresh Workflow | local refresh of the Workflow tab only |
| `NONE` | no button | none |

Recommended button behavior:

- Display one report-level button for `report.recommended_tool`.
- Optionally display deduplicated action-level buttons for tools found in `report.next_actions`.
- Hide buttons when no existing GUI method is mapped.
- Never call `CollectorWorkflowEngine` directly from button handlers.
- For `WORKFLOW`, use the existing workspace refresh path instead of opening a new tool.

## 4. Refresh Behavior

The existing `Refresh Workspace` button should continue to call:

```python
workspace.refresh()
self._refresh_workspace_tabs(tabs, workspace)
```

Phase 4 should update refresh wiring:

- `workflow` tab refresh calls `workspace.get_workflows()`.
- The Workflow tab text is replaced with `_format_unified_workflow(report)`.
- Workflow buttons are rebuilt or refreshed so they match the current report metadata.
- Workspace cache behavior remains owned by `CollectorWorkspace`.

No persistence is added. Refresh does not mutate the collection.

## 5. Error and Empty-State Behavior

The GUI should not catch workflow engine exceptions directly. It should rely on `CollectorWorkspace.get_workflows()` to return a degraded `UnifiedWorkflowReport`.

Display behavior:

- `BLOCKED`: show state, state reason, warnings, and evidence.
- `NEEDS_INPUT`: show state reason and next action.
- Empty evidence: show `No workflow evidence available.`
- Empty actions: show `No workflow actions available.`
- Missing tool metadata: show `Recommended Tool: N/A` and no tool button.
- Unknown `RecommendedTool`: show the label if present, but do not create a button.

No message boxes are needed for read-only display errors. The error belongs in the tab text.

## 6. Test Plan

Recommended tests should stay focused and avoid launching a real GUI.

Unit-style tests:

- `_format_unified_workflow()` includes workflow type, state, `state_reason`, recommended tool label, actions, evidence, and warnings.
- `_format_unified_workflow()` handles missing evidence/actions gracefully.
- Tool mapping resolves known `RecommendedTool` values to existing method names.
- Tool mapping returns no command for `NONE` or unknown metadata.
- Workflow tab creation calls `workspace.get_workflows()`, not `workspace.get_workflow_status()`.
- Refresh wiring refreshes the workflow tab with `workspace.get_workflows()`.
- No direct `CollectorWorkflowEngine` imports or calls are introduced in GUI workspace code.

Regression tests:

- `python -m unittest test_collector_workspace.py`
- GUI-focused tests if an existing GUI test module is available or a small non-launching formatter test module is added.
- `python -m unittest discover`

Manual smoke test after implementation:

- Open Collector Workspace.
- Confirm the Workflow tab displays the Daily Inbox unified workflow.
- Confirm buttons only appear for mapped existing tools.
- Confirm Refresh Workspace updates the Workflow tab.
